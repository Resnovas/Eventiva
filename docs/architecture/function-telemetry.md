### Proposed shared compiler-applied mechanism

Proposal, proof-only pending Jonathan's build-time decision: use the installed TypeScript compiler to generate function/step instrumentation from authored declarations, not manual business-body calls. One transform supplies all target adapters and an emitted coverage manifest. The first implementation slice inventories syntax and proves semantics before any build route is rewired.

- Keep synchronous functions synchronous: generated entry/exit hooks around their original bodies preserve declarations, receiver, arguments, arity, return/throw, closure and evaluation order. Do not turn pure APIs into Effects.
- Instrument Effect operations at actual lazy execution, using named Effect span semantics and bounded all-exit local counter/histogram completion. Service/Layer/ActionBinding registration supplies static descriptors and existing Flags/context once. Do not measure only Effect/Layer/Stream construction or blindly double-instrument existing operation spans.
- All exits include success, typed failure, defect and interruption. Preserve the original exit, environment, scope/finalizers and cancellation ownership. Instrumentation performs no sink/plugin IO inside business transactions or finalizers.
- Generate fixed operation/step identifiers with capacity8,192; do not use Function.name, arguments, stack/source paths or arbitrary runtime names as emitted attributes. Source paths may appear in offline blocked-occurrence reports, not as collected telemetry labels.
- Per-step profiling uses explicit executable source/control-flow segments, stable matching within current/candidate measurements and monotonic time. Native span timestamps are intrinsic span lifecycle; the optional timer flag governs additional step-duration profiling. Iteration/suspension/finalization need their own semantic controls, not misleading whole-function averages.
- Generated coverage checks compare original executable function inventory, generator output and actual emitted/loadable artifacts. Text containing a wrapper name is not coverage. Unresolved dynamic boundaries/runtime targets are BLOCKED, not accepted debt.
- Collector self-observation needs a finite non-export-recursive mechanism. Instrumentation helpers remain in inventory; no reentrancy boolean silently exempts their executions. This is an explicit feasibility obligation, not a solved implementation detail.

The transform proposal is not yet qualified for constructors/super, parameter initializers, async/generator lifetimes, React/framework semantics or fiber-safe synchronous parent context. Report exact unsupported occurrences and preserve them until proved. Do not ship a partial compiler pass under an every-function compliance claim.
