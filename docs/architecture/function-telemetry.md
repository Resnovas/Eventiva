## Instrument execution once through the existing stack

Proposed portable API: a generic `FunctionTelemetry` Context service in existing contracts/observability, with an `observe` method accepting a static operation descriptor and an Effect. It preserves success type, error type, required business services, laziness and interruption. Accessing the service adds the explicit instrumentation service requirement. Implementation lives beside central runtime telemetry and is supplied once at composition. Integration modules depend on the contract, never import runtime; no new package or dependency is required.

The descriptor contains a reviewed stable operation ID, module ID, profile and finite semantic attribute values. It accepts no argument/result serializer, arbitrary error classifier, user callback or exporter. A generated build-time operation catalog supplies constants; do not use Function.name, source paths, stack traces, user-provided names or resource identifiers.

On each actual execution, not Effect construction:

1. Increment started, read the monotonic clock and open exactly one child span under current context; a root span is created only without a trusted parent. Disable stack capture.
2. Run the original Effect exactly once, with the same environment and cancellation ownership. Existing resource/kernel spans are adopted as the operation boundary, not blindly double-wrapped.
3. In bounded local exit finalization, record duration for success, typed failure, defect and interruption; increment one completion counter with a closed outcome; close the span once. Never serialize Exit.value/Cause or alter the original exit.
4. Use existing Effect Metric counters/histograms for local aggregation. Keep metric names fixed: proposed `eventiva.function.started`, `eventiva.function.completed`, `eventiva.function.duration_ms`; labels come only from the finite catalog/outcome set. Do not allocate metric names/labels from requests.
5. Central telemetry continues to sanitize and queue spans. No sink IO or arbitrary plugin callback runs inside a business transaction, metric update or finalizer. Exporter failure cannot alter business results. Producers expose bounded drop/failure health rather than recursive telemetry about their own telemetry.

A function returning an Effect is measured when that Effect executes. A Layer factory is observed at acquisition/release, not just construction. Methods implemented by a service are covered even when the implementation is an object arrow rather than an exported declaration. Streaming operations need an explicit acquisition/use/release descriptor, rather than incorrectly timing only Stream construction. Pure synchronous APIs must not become Effect-returning APIs merely to satisfy a checker without an approved compatibility transition.

No new automatic metrics network exporter is proposed in the primitive. A later versioned metric-record/provider boundary must preserve current export authority/profile/live-grant rules and be separately tested before any remote metric ingestion. Span instrumentation must not imply audit, durable delivery or exact-once external effects.

## Naming, minimization and trust rules

- Stable span IDs use `eventiva.<module>.<operation>`; attributes use existing semantic keys where present, plus reviewed `eventiva.function.id`, `eventiva.module.id`, `eventiva.function.outcome` and existing `eventiva.profile`. Names are compile-time catalog identifiers, not function arguments. Restrict outcomes to succeeded/failed/defect/interrupted; intentional business denial remains a separately declared bounded outcome, not error text.
- Never record names/emails/addresses, bearer/session tokens, credentials, environment/config values, headers, SQL parameters, raw URLs/paths, request/response bodies, prompts, customer data, argument/result dumps, Error.message/stack/Cause, or user-chosen operation names. Hashing does not make an arbitrary secret/identity acceptable.
- Trace/span IDs are correlation only and never authentication. Do not label metrics by trace/session/tenant/user/resource/execution ID, even pseudonymous. Preserve existing Restricted/Vault no-application-metadata behavior; do not attach hidden identity to metrics or error labels.
- Core policy is finite allowlisting at collection. Export applies the existing independent live authority/purpose/profile/destination rules again. Invalid/unlisted attributes are dropped with safe bounded counters, never echoed in diagnostics. Static strings in a catalog still require human privacy review.
- Instrumentation uses no new payload-bearing span events/links, stack capture, automatic argument introspection or resource metadata. Do not broaden the already reviewed private vendor callback opacity exception.

## Enforce the invariant through code, checks, then prose

Invariant: every in-scope operation execution passes through the approved wrapper, preserving behavior while producing one complete local observation of every exit, with catalog-only metadata. The checker proves wrapper coverage; public telemetry tests prove its semantics. Neither proves business correctness alone.

1. Codebase: implement/test the one primitive and migrate a representative operation first. Inventory every authored exported function, default export, re-exported local implementation, service method and Effect/Layer factory with the existing TypeScript compiler API. Resolve actual bindings, not names or text searches. Include private nontrivial functions in the final inventory and choose approved exception classification per the owner decision.
2. Static analysis: built-in no-restricted-imports prevents direct vendor/exporter/console bypass but cannot establish function instrumentation or alias/re-export coverage. Prefer a small TypeScript-resolved verification extension using the installed compiler, rather than a custom framework/dependency. It must reject unwrapped public implementations, partially wrapped return paths, shadowed fake wrappers, arbitrary Effect.withSpan without metrics and dynamic operation IDs. Extend ordinary ESLint only for the restrictions it can express honestly.
3. Fix-oriented error: `Exported operation <module>.<name> bypasses function telemetry. Wrap its entire execution with FunctionTelemetry.observe using a registered static operation descriptor; for an approved tiny pure helper, use the checker-recognized pure form. Do not add an inline suppression.` If bodyless exports or syntax cannot establish the intended classification, report the exact binding for review instead of guessing.
4. Required verification: wire inventory/check and its negative/positive fixtures into root check and uncached Nx verification; full verify already consumes root check. Demonstrate original public uninstrumented code rejected, the migrated wrapper accepted, and a nearby legitimate pure selector/bodyless declaration accepted. Include aliases, object methods, reexports, currying, branching, overloaded/anonymous/default functions and sibling false-wrapper controls. Type tests prove A/E/R and sync API preservation. No regex-only presence test or custom static call-graph guess claims complete behavior coverage.
5. Migration has an explicit reviewed phase/path inventory, not an accepted-debt baseline. Each migrated slice blocks all its violations. Unmigrated slices remain visible as incomplete and cannot be labeled repository-wide compliant. Enable the final global gate only when the inventory reaches zero unapproved occurrences. Do not add suppressions or relabel unread findings as exceptions.
6. AGENTS.md: only after the check exists, retire duplicate local enforceable instructions and keep privacy judgment, semantic operation selection, measured hot-path review and owner approval. Do not preemptively rewrite managed house prose. Promote a generally applicable checker/template through Resnovas/.github's normal PR/checks after local proof and owner policy decisions, not through this planning commit.

## Assert execution with spans, metrics and independent behavior checks

Extend existing public-path tests with an in-memory TelemetrySink and real central telemetry layer. After deterministic scope closure/flush, assert exact operation multiplicity, parent/child ancestry, safe attributes, closed outcome and duration. Do not snapshot opaque IDs or total scheduling order between concurrent siblings. Test awaited children versus detached work explicitly; a span is not proof of durable outbox propagation.

Use TestClock for deterministic logical duration on ordinary Effect paths; use monotonic real-time measurement for actual subprocess/OS work with unchanged deadlines. Metric.value before/after deltas should prove one started and one completed counter plus one histogram sample for success, typed failure, defect and interruption. Effect's default registry is process-wide: run shared metric-key fixtures serially in an isolated worker/process, take bounded deltas and await all fibers before reading. Do not reset a global registry while other tests execute or introduce per-run random production labels to obtain isolation.

Prove missing/false instrumentation admission in tests, independent optional production opt-out, queue saturation/drop, sink outage, flush/shutdown and nonrecursive internal telemetry. Redaction canaries must fail if reflected into any collected record/metric label/export request. Preserve the exact value/error/defect/interruption, finalizer counts and transaction/audit outcomes; telemetry assertions supplement existing business assertions and never replace them. Counters balance only after all started fibers close; abandoned/cancelled work must not be mislabeled succeeded. Existing version-1 local span outcome collapses failures, so distinguish defect/interruption via approved outcome metadata without changing wire semantics silently.
