# Neon SQL compatibility and safe conformance

Neon is the intended production PostgreSQL provider: one dedicated project per tenant in AWS London (`aws-eu-west-2`). Generic PG17 Docker is local/CI tooling, not a production provider. Documented compatibility is not live validation of the exact pinned driver stack.

Reviewed 2026-11-15 against official sources below. Approved libraries: `@effect/sql@0.52.2`, `@effect/sql-pg@0.53.1`, `pg@8.23.1`; Node SQLite conformance uses `@effect/sql-sqlite-node@0.54.1` and `better-sqlite3@13.0.3`, with development-only `@types/pg@8.23.1`. No Drizzle, serverless HTTP driver, extension or sync SDK is added.

## Compatibility matrix

| Area             | Required treatment                                                                                                                                                                                               | Evidence boundary                                                                                                                                     |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Version/region   | Explicit PG17; dedicated project in `aws-eu-west-2`. Region is fixed at project creation.                                                                                                                        | [Compatibility][1], [regions][2]. Branches inherit region; branch-per-tenant is not equivalent to project-per-tenant.                                 |
| Query pooling    | Ordinary TCP SQL may use the `-pooler` endpoint with bounded application pools. PgBouncer is transaction pooling, not 10,000 simultaneous running transactions.                                                  | [Pooling][3]. Test exact Effect/pg stack separately from direct routes.                                                                               |
| Migration route  | Use direct non-pooler endpoint and separate migration identity. Transaction advisory locks are acquired and released inside the same transaction.                                                                | [Pooling][3]. No session advisory lock or session `SET` dependency.                                                                                   |
| TLS              | Use verified TLS and negative certificate/hostname tests. `pg` URL SSL parameters can replace explicit SSL configuration. Do not assume libpq channel-binding URL flags are supported by this exact adapter.     | [Secure connections][4], [pg SSL][5]. `require` descriptions vary; choose `verify-full`.                                                              |
| Transactions     | Bind handler, history, outbox, receipt and dedup to one acquired connection. Test lock waits, concurrent duplicate keys, savepoints and rollback for failures/defects/interruption.                              | [Pooling][3]; local PG17/SQLite conformance is independent of Neon validation. Cancellation through a pool is best-effort and needs provider testing. |
| Session features | No persistent search path, session settings, session locks, LISTEN or SQL PREPARE through pooled runtime. Use transaction-local context for RLS.                                                                 | [Pooling][3]. Protocol prepared statements are distinct from SQL PREPARE.                                                                             |
| Lifecycle        | Release pools, bound acquisition, test natural suspension and reconnect. Idle-in-transaction or CDC subscribers can prevent suspension. Never blindly retry ambiguous commits.                                   | [Lifecycle][6]. `suspend_timeout_seconds=0` does not establish actual suspension behavior.                                                            |
| DDL/extensions   | Baseline uses normal PG17 tables/indexes/triggers and plpgsql, no extension. No superuser, filesystem/tablespace or unsupported instance configuration assumptions.                                              | [Compatibility][1], [extensions][7]. Durable state must not use unlogged tables, which lose contents on restart/suspend.                              |
| Test isolation   | Branches clone parent data, roles and databases. Begin from an empty approved synthetic project; never branch production data for this test.                                                                     | [Branching][8]. A branch is a test boundary, not production tenant isolation.                                                                         |
| Routing/RLS      | Trusted authenticated routing selects project/database/role; reject absent, revoked or inconsistent scopes. Keep runtime non-owner/no BYPASSRLS; test control-plane row policies with transaction-local context. | [Roles][9], [RLS][10]. Ordinary pg does not automatically inject Data API `auth.user_id()`. SQL roles do not authorize Neon management API calls.     |
| Integer/decimal  | Safe integer quantities/versions; unrestricted exact money/decimal values stay strings. Test values around 2^53 and int64 endpoints, arrays and aggregates.                                                      | [pg types][11]. Never unconditionally convert bigint to Number.                                                                                       |
| Time             | Contract is exact integer milliseconds; PG uses timestamptz, SQLite epoch milliseconds. Default pg Date truncates microseconds. Test year 1/9999, offsets and DST boundaries.                                    | [pg types][11]. Microsecond-exact contracts would need a different codec.                                                                             |
| UUIDv7           | Application generation; native PG17 uuid stores v7 but does not enforce its version. No dependency on PG18 uuidv7() or extension availability.                                                                   | [Extensions][7], [PG UUID][12].                                                                                                                       |

A custom suspend interval was rejected with HTTP 412. Do not assume scale-to-zero.

Quotas reported: 36,000 active seconds, 9,000 compute seconds, 100 MiB written data, 1 GiB transfer and 100 MiB logical size. Initial reported usage counters were zero; this is a measurement, not a guarantee of instant counter freshness. Minimize idle compute and inspect usage before/after each bounded run. The initial project-level logical-size metadata also reports 1 GiB; honor the stricter 100 MiB quota.

Earlier read-only follow-up reported 68 active seconds and 19 compute seconds, with written/transfer/storage counters still zero. The endpoint reported `idle` and `suspended_at=2026-11-15T04:03:16Z`, despite timeout metadata being zero. This is evidence of suspension after provisioning, not a tested query/reconnect cycle or usage attributable to this conformance suite. It also reported `pooler_enabled=false` while advertising a pooled host. Subsequent live validation below connected through that pooled host without changing any endpoint setting; the metadata flag alone did not predict its reachability.

The historical PG16 Frankfurt project `cool-unit-72575963` is protected and must not be changed, queried for conformance, branched or used for credentials. No more projects, plan changes, CDC enablement or app infrastructure are authorized.

The project-scoped Amp secret `EVE_NEON_TEST_DATABASE_URL` was privately saved and loaded with `amp orb restart-processes`. An initial owner/admin-identity stop was later explicitly superseded by the owner's authorization to use that existing full-access identity for bounded synthetic development validation. Direct and pooled hostnames came from the approved branch's read-only endpoint inventory, not inference from another URL. ## Executed synthetic validation (2026-11-15)

The pinned Effect PostgreSQL adapter connected on both direct and pooled routes to `eventiva_dev`, PostgreSQL 17.12. Both routes used authenticated TLS 1.3, and the pinned pg driver rejected an intentional certificate-hostname mismatch on each. Client socket verification was positive while backend `pg_stat_ssl` reported false; this validates the client-to-endpoint TLS connection, not every internal provider hop. The supplied connection was Neon-admin/BYPASSRLS but not PostgreSQL superuser, consistent with the explicit test-only exception.

A bounded scratch probe passed 16 checks against a uniquely named synthetic schema, which it removed before closing all clients. Direct migrations applied, reapplied and rejected an altered checksum. Pooled ordinary SQL atomically committed domain/history/outbox/dedup/receipt, replayed identical keys, rejected changed hashes and rolled back typed failure, defect and interruption. Concurrent duplicate keys executed once; competing CAS writes and scarce reservations admitted one winner. Values preserved int64 endpoints, exact decimal scale and money above 2^53, application UUIDv7 and millisecond instants from year 1 through 9999. An additional native-result query preserved bigint/numeric strings, bigint arrays and a sum exceeding int64 without text casts. Missing/mismatched tenant scopes were rejected before route resolution. These outcomes agree with the corresponding pinned local PG17/SQLite scenarios; this remote probe is not the entire 29-test local suite and does not prove production cross-project isolation or cluster/process recovery.

Role-catalog assertions confirmed both `eventiva_test_runtime` and `eventiva_test_migrator` lack superuser, CREATEDB, CREATEROLE, REPLICATION, BYPASSRLS, neon_superuser membership and database CREATE. Runtime lacks CREATE on public; migrator has it. A separate transaction-rolled-back probe failed at `SET LOCAL ROLE eventiva_test_migrator` with SQLSTATE `42501`, before creating its synthetic table. Consequently effective restricted-role DDL/DML/default-grant/RLS and independent login tests were not executed. No grants, memberships, role attributes or passwords were changed to bypass that failure. Restricted-role credentials are not a blocker to the owner's authorized full-access development validation, but it must not be presented as least-privilege production acceptance.

Before/after inventory snapshots at 11:20:46 and 11:26:01 UTC both reported 608 active seconds, 156 compute seconds, zero written bytes and 616 transfer bytes despite confirmed synthetic writes. These readings cannot yet attribute consumption to this run and do not prove zero cost or zero data written. Honor the stricter quotas above; no more SQL was run to wait for billing counters. Clients were closed, but endpoint metadata still said active with suspend timeout zero. Autosuspend behavior and exact usage attribution remain unverified. Replication stayed disabled, and no historical project, plan or provider infrastructure was changed.

## CDC and cost gate (deferred)

[Logical replication][13] is per-project, changes wal_level for all databases, is irreversible once enabled, and restarts every compute, dropping connections. A connected subscriber prevents scale-to-zero even without ordinary queries. CDC needs a direct non-pooler endpoint and a dedicated correctly privileged replication role, separate from runtime/RLS roles. Test ordinary pooled Effect SQL independently.

Slots can be removed after approximately 40 hours without acknowledged flush progress; that is not a retention SLA. Branch restore removes slots. Defaults are 10 WAL senders and 10 replication slots, not guaranteed free capacity. Do not enable replication or create slots/subscribers during SQL-only conformance.

A later synthetic-only PowerSync trial needs separate approval for the irreversible setting, restarts, subscriber infrastructure, duration/budget and cleanup/recovery. Measure baseline versus subscriber-connected active time/CU-hours, slot lag and retained WAL, reconnect/resnapshot, SQL performance and compute/storage/history/transfer/subscriber costs. A 40-hour experiment or restore test requires explicit authority. Published [plans][14] are not account-specific quotes. At 0.25 CU continuously for 730 hours, compute alone is 182.5 CU-hours; the subscriber may remove expected autosuspend savings. Report measured economics and a proposal before broad tenant rollout; do not replace dedicated production projects with branches.
