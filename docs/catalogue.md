# Supplier stock import preview (EVE-247)

## Authority and scope

Jonathan resumed the explicitly named EVE-247 work on 2026-11-18 in [the owner message](https://ampcode.com/threads/T-01a1e940-37a3-7691-a5c0-e935b711c99a#M-034zciY2mZuppwjcEvwc6g). [EVE-247](https://linear.app/resnovas/issue/EVE-247) retains the research and licensing deliverables; building a bounded preview does not establish those findings or complete EVE-81's catalogue/inventory implementation.

The first slice exports `@eventiva/contracts/catalogue`. It separates public manufacturer/model references from tenant-private supplier SKU and quantity rows. It accepts already-mapped records only: it is not a CSV parser, scraper, external feed or production importer. No dependency, external request, supplier outreach, stock write, shared publication or model training occurs.

## Preview mapped bulk rows

1. Supply an authorized reference list containing only `id` (UUID), `manufacturer`, `model` and `variant` (string or `null`). A reference cannot contain supplier quantities, prices or serials.
2. Map each tenant-private bulk row to `supplierSku`, `manufacturer`, `model`, `variant` and `quantity`. Keep private rows out of shared catalogues and telemetry.
3. Call `previewStockImport(rows, references)` inside Effect. Correct every invalid, duplicate, unmatched or ambiguous result before any future staged commit.

Names and SKUs are nonempty trimmed strings of at most 200 characters. Quantities are nonnegative safe integers; zero is valid. All fields are required with no defaults; unknown fields reject a row. Containers are bounded to 1,000 stock rows and 10,000 public references. These are conservative, reversible implementation limits, not researched coverage claims or separately approved business targets.

The full executable example is [the contract test](../tests/contracts/src/catalogue.spec.ts): public `Fixture Audio` / `A-10` / no variant matches private `fixture audio` / `a-10` / no variant, SKU `S-01`, quantity 3. The result is row 1, state `matched`, reference UUID plus a detached validated private stock row. `A10`, a different manufacturer, or variant `mk2` does not match that reference. Case alone is ignored; punctuation, spaces and revision suffixes are retained. Nothing is silently fuzzy-matched.

| Preview state   | Meaning                                                                                            |
| --------------- | -------------------------------------------------------------------------------------------------- |
| `matched`       | One exact model identity; carries private validated stock for a later authorized staging flow      |
| `invalid`       | Row schema rejected; result includes only position and state, not rejected values                  |
| `duplicate-sku` | More than one valid row has the same case-insensitive supplier SKU; every colliding row is refused |
| `unmatched`     | No exact manufacturer/model/variant identity; manual review required                               |
| `ambiguous`     | Multiple reference rows match; no arbitrary winner                                                 |

Positions are one-based and preserve invalid rows. Repeating a preview produces the same result without writing anything; this is not durable import idempotency or undo. Malformed/oversized containers and invalid public references fail the whole Effect with a typed Schema parse error. Such errors can include source values and must not be sent to telemetry. Row validation failures use the bounded `invalid` result instead. Kits, assets/serials, prices, CSV bytes, column mapping, unit transforms and partial commits are deliberately not interpreted.

The two manufacturer samples cover microphones and powered loudspeakers only. They do not establish coverage for lighting, rigging, power, video, staging, discontinued models or regional revisions. Conflicting facts must remain separate source/version assertions pending review, not last-write-wins technical truth. Candidate provenance fields for a later reference revision are source URL, retrieval time, source revision if known, value/unit, reviewer and rights disposition. Supplier-private quantities, pricing and reservations belong to separate tenant records and never inherit public provenance merely by matching a model name.

For the next zero-acquisition-cost pilot, use consented, redacted supplier exports mapped to bulk stock only. The initial engineering acceptance choices are zero false automatic matches in a reviewed fixture set, explicit correction outcomes for every input position and unchanged inventory after preview or cancellation. These are conservative implementation gates, not researched product search-coverage targets or Jonathan-selected numerical values. Any fuzzy search suggestion must remain distinct from a confirmed exact model match. Retain synthetic automated fixtures until redistribution permission for real samples is established.

Supplier discovery remains unperformed: no interviews, survey or representative sample supports a claim that these two tools dominate. Actual export compatibility, legal permission, realistic search quality and end-to-end import success rates remain open.

## Remaining research and implementation

First validate source rights and recruit a consented supplier sample; prioritize connectors only from observed export evidence. Then implement mapped CSV preview and a correction/review journey under EVE-81: map columns, preview every row, correct invalid/duplicate/unmatched/ambiguous identities, and confirm the staged batch explicitly. Cancellation must leave stock unchanged. Only a later tenant-authorized persistence slice may add idempotent re-import, relationship ordering, durable audit and rollback; repeated local previews are not proof of those properties. Search-add and collaborative manual entry must use the same reviewed identity rules without forcing incomplete specifications to block quotations.

Keep public model provenance/version/conflict review distinct from private ownership, reservation, price and publication controls. All user/agent surfaces must share the existing action authorization and private-stock opt-out. The portable library currently has no application registration or runtime behavior to flag; a future importer must be default-off. EVE-247 remains open until its evidence, journeys and phased acceptance metrics are actually reviewed.
