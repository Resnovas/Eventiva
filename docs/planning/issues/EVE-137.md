## Goal

An enquiry from a website form, email or phone call becomes a tracked opportunity that moves through stages and, when won, becomes an event with its client and contacts already attached.

## Context

* Parent [EVE-65](<https://linear.app/resnovas/issue/EVE-65/f4-contacts-and-crm-people-organisations-relationships-and-history>) sections 4 (enquiry, opportunity, pipeline actions), 6 (Pipeline board, Enquiry inbox) and decision D2 (pipeline lives in F4; recommended). If Jonathan picks D2 B, this issue moves to F9 unchanged.
* Event and event templates are F1 entities; `convertToEvent` calls F1's create action, it does not write F1 tables.
* Proposals, quotes and deposits are F9 and F11; an Opportunity only carries an estimated value.
* Public forms come from the F14 website builder later; this issue ships a hosted form endpoint and an embeddable snippet with a per-tenant token.
* F5 directory (<issue id="b22fbb0d-100b-47a3-8c32-eeacadc4c9fe" label="EVE-66" href="https://linear.app/resnovas/issue/EVE-66/f5-directory-and-marketplace-vendor-venue-and-professional-listings" />, <issue id="03bd23d1-9da5-4272-8f2e-0b0bf4f7f846" label="EVE-119" href="https://linear.app/resnovas/issue/EVE-119/f57-build-cross-tenant-enquiries-rfps-and-private-message-threads" /> item 10, <issue id="f08bafe4-f32d-4906-9e87-5d69df56d6a0" label="EVE-124" href="https://linear.app/resnovas/issue/EVE-124/f58-build-quotes-quote-comparison-and-the-acceptance-handoff-to-the" />) calls `crm.enquiry.capture` as a system principal acting for the vendor tenant, stores the returned id as `crmEnquiryRef`, and calls `crm.enquiry.resolve` on quote acceptance or decline. The system principal is scoped to `crm.enquiry.capture` and `crm.enquiry.resolve` in that tenant only, and every call is audited with the F5 thread id as source.

## Scope

1. Tables `enquiry`, `pipeline`, `stage` (order, probability, won or lost flag), `opportunity`.
2. Actions `crm.enquiry.capture` (public token, rate limited, spam checked by honeypot and time-to-submit, no vendor captcha), `crm.enquiry.qualify` / `discard` / `match` / `resolve` (outcome won or lost with reason; if the enquiry has an opportunity, it also calls `markWon` or `markLost` on it; status gains won and lost), `crm.opportunity.create` / `update` / `moveStage` / `markWon` / `markLost` / `convertToEvent` (confirm), `crm.pipeline.define` / `update`.
3. Default pipeline per tenant: New enquiry, Qualified, Site visit, Proposal sent, Negotiation, Won, Lost (editable).
4. Stage conflict rule from the parent (server order; stale won or lost rejected back to the user).
5. Convert to event: creates the F1 Event from a chosen template with `Event.client_ref` set to the opportunity's party ([EVE-73](<https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show>)), adds the opportunity's other contacts as EventRoles (F4.2), links the opportunity, logs an Interaction (F4.3).
6. Screens: Enquiry inbox, Pipeline board, Opportunities tab on detail pages. Flag `crm-pipeline`.

## Acceptance criteria

* Tests: a form post creates an Enquiry and matches an existing person by email; a system principal for tenant A can capture and resolve in A and is denied in tenant B and on every other CRM action; resolve won on an enquiry with an opportunity marks the opportunity won; a stale offline move to won is rejected with a typed error; convert creates exactly one event even when retried.
* The agent turns "Sarah from Acme rang about a 200 person launch in March" into a person, organisation, enquiry and opportunity, and asks before converting.
* `node --run check` green.

## Constraints

Effect-TS v3; public endpoint rate limited and audited; whitelabel form copy; no new dependency without approval here; ship to main with check results.
