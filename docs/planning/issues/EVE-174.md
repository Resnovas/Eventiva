## Goal

Orders can be paid online by card through a neutral PaymentGateway port, with each tenant connected as its own merchant, verified webhooks, and no card data ever touching Eventiva.

## Context

* Parent <issue id="7d939472-20ba-4512-b231-c0f04c05574c" label="EVE-107" href="https://linear.app/resnovas/issue/EVE-107/f9-online-and-in-person-sales-storefront-point-of-sale-orders-payments" /> sections 8 and 11, decision D2 (recommended: Stripe with Connect, tenant as merchant of record). Do not sign up or add the SDK until Jonathan approves D2 and the dependency on this issue.
* Webhook endpoint served by <issue id="0ab161c4-ed9c-4581-86fe-91fa1f4216aa" label="EVE-46" href="https://linear.app/resnovas/issue/EVE-46/p17-build-the-http-api-streaming-and-the-typed-client-from-the-action" /> HTTP API; provider secrets through <issue id="9d08c369-bac9-4eb7-b8a7-329b5ec9bff0" label="EVE-41" href="https://linear.app/resnovas/issue/EVE-41/p12-build-app-config-settings-secrets-and-credentials" /> credentials, never in actions, logs or agent context.

## Scope

1. `PaymentGateway` Effect service (integration package `integrations/payments-<vendor>`): createPaymentSession (hosted fields or hosted page, 3DS), capture, void, refund, getPayment, verifyWebhook, connected account onboarding link and status, listPayouts. Typed errors: Declined, AuthenticationRequired, ProviderUnavailable, InvalidRequest.
2. A fake gateway Layer for tests and local development (no network), used by every other F9 slice.
3. First vendor adapter per D2.
4. Actions: sales.payment.create, capture, void, recordWebhook; sales.settings.connectProvider, disconnectProvider (approval always).
5. Payment state machine: pending, authorised, captured, failed, voided; webhooks are the authority; replayed webhooks change nothing (stored event ids).
6. Payments settings screen showing connection status only.

## Acceptance criteria

* With the fake gateway: pay, 3DS required then completed, decline, provider outage (retry with backoff, order stays placed), webhook replay; all tests green.
* Sandbox test against the real adapter (once approved): one payment, one refund, one webhook, recorded in a comment with ids redacted.
* Secret scan shows no provider keys in the repo; telemetry inspection shows no card data or emails.
* Disconnecting the provider blocks new payments with a typed error and leaves existing orders readable.
