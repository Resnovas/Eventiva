## Linear description

## Goal

Every worker, freelancer, volunteer and supplying agency manages their own HR data in the same Eventiva app on phone, desktop and web, and a site supervisor can check crew eligibility at the venue with no signal.

## Context

* Parent: [EVE-80](<https://linear.app/resnovas/issue/EVE-80/f13-human-resources-worker-records-onboarding-qualifications-and-leave>), sections 6 (Screens), 9 (roles including supplying agency) and 12 (offline site check acceptance).
* Screens use Rambo-UI components and declare screen-context projections with every control bound to an action ([EVE-50](<https://linear.app/resnovas/issue/EVE-50/p111-build-screen-awareness-app-state-navigation-and-the-screen>)). The settings and profile shell comes from [EVE-32](<https://linear.app/resnovas/issue/EVE-32/port-settings-profiles-navigation-command-menu-and-onboarding>). Screens ship as a federated module with a bundled fallback ([EVE-16](<https://linear.app/resnovas/issue/EVE-16/s3-prove-runtime-loading-and-switching-of-a-remote-module-on-expo-web>)) so they work offline.
* Blocked by F13.4 (<issue id="576185f3-f438-43c7-b694-e5afff0605e7" label="EVE-153" href="https://linear.app/resnovas/issue/EVE-153/f134-build-onboarding-and-offboarding-runs" />), F13.5 (<issue id="9f305527-7de1-436f-89bd-27341f70624e" label="EVE-154" href="https://linear.app/resnovas/issue/EVE-154/f135-build-qualifications-requirements-and-the-eligibility-check" />) and F13.7 (<issue id="5ca54321-0f0a-461c-ade1-89cf3197dc48" label="EVE-179" href="https://linear.app/resnovas/issue/EVE-179/f137-build-leave-policies-the-leave-ledger-requests-and-absence" />) for the actions these screens call.

## Scope

1. `me.profile` (own non-sensitive and sensitive fields, emergency contacts, data export), `me.documents` (to sign, signed, upload), `me.qualifications` (add with photo or file, see expiry), `me.leave` (balance, request, history).
2. Supplying agency view: list of their supplied workers, add and update qualifications and documents for them, see eligibility only for them.
3. HR screens from <issue id="253839bc-c987-416b-92ea-206c9e9e8d2e" label="EVE-80" href="https://linear.app/resnovas/issue/EVE-80/f13-human-resources-worker-records-onboarding-qualifications-and-leave" /> section 6 not already built in earlier slices: `hr.people`, `hr.worker`, `hr.orgChart`, `hr.qualifications` matrix, `hr.compliance`.
4. `hr.siteCheck`: search or scan a worker code, show eligibility and induction status for the supervisor's current F1 Event as of last sync, record induction; clear offline banner with the last sync time.
5. A scannable worker code (QR) on `me.profile` that carries an opaque id only, no personal data.
6. Each screen's projection registered on module activation and removed on disposal; a CI fixture with an unbound control fails the check.
7. Accessibility to WCAG 2.2 AA (house `web-accessibility` skill); localisation-ready strings (<issue id="338aae77-d10e-4f8a-9189-fe3655bd3572" label="EVE-28" href="https://linear.app/resnovas/issue/EVE-28/port-localization-for-people-and-for-the-agent" />).

## Acceptance criteria

* A freelancer completes their onboarding entirely from a phone: signs two documents, uploads a certificate, sets emergency contacts.
* An agency user sees only their own supplied workers (negative test).
* With the network off, a supervisor scans a worker code, sees eligible or not with reasons and the last sync time, records an induction, and it syncs on reconnect.
* The agent reading `hr.qualifications` sees the same visible cells as the user and can perform every visible control through its action.
* axe reports no serious or critical issues on each screen on web.

## Constraints

Rambo-UI components only (request missing ones in Rambo-UI rather than building local copies); Effect-TS v3 house rules for any data access; no new dependency without Jonathan approving it on this issue; behind `hr-module`; ship to main per the AGENTS.md delivery exception with `node --run check` results pasted here.
