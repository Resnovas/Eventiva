## Goal

An organiser assigns a task to a vendor or freelancer who is not a member, and that person sees and completes only their own tasks in the same app.

## Context

* Parent spec: <issue id="4e19a499-139f-4016-88c4-264d3a0f7c33" label="EVE-62" href="https://linear.app/resnovas/issue/EVE-62/f3-tasks-task-lists-assignments-dependencies-and-checklists-per-event" /> sections 4 (`guest.inviteToTask`), 9 (guest row), 11 (guest terms and data limits).
* Guest principals and scoped access come from <issue id="7f612e80-3332-4acf-a74c-d35db06fe4e8" label="EVE-43" href="https://linear.app/resnovas/issue/EVE-43/p14-build-identity-and-access-orgs-authorization-user-profiles-and" />; sync-time authorization and revocation from <issue id="a1348819-43cc-4005-8e8d-a896a761af03" label="EVE-51" href="https://linear.app/resnovas/issue/EVE-51/p112-build-collaboration-yjs-for-text-and-canvas-with-record-sync-and" />; invite email from <issue id="9aae6a50-4a43-4327-ae6a-51d18bc69b35" label="EVE-24" href="https://linear.app/resnovas/issue/EVE-24/port-notifications-messaging-channels-and-transactional-email" />.
* F4 will own Contacts; until it lands, a guest is identified by email only, and F4 links the contact later without data migration (guest keeps the same principal id).

## Scope

1. Guest principal type in the tenant (<issue id="7f612e80-3332-4acf-a74c-d35db06fe4e8" label="EVE-43" href="https://linear.app/resnovas/issue/EVE-43/p14-build-identity-and-access-orgs-authorization-user-profiles-and" />), scoped to a set of task ids, no member list and no other Event data beyond the Event name and the task's dates.
2. Action `guest.inviteToTask` (external side effect, confirm): sends an invite, creates or reuses the guest, assigns the task. `guest.revoke` removes access.
3. Guests sign in with the same app (one app rule from the project brief); their navigation shows only My tasks and Task detail.
4. Sync filter: a guest device receives only assigned tasks, their checklists and comments on them; revoke removes them on next sync.
5. Guest terms acceptance on first sign-in, recorded.
6. Flag `tasks-guests`, default off.

## Acceptance criteria

* A guest assigned 2 of 50 tasks on an Event sees exactly those 2 through UI, HTTP and MCP; listing other tasks returns nothing, not an error that leaks counts.
* Revoking the guest removes both tasks from their device on next sync.
* A guest can complete their task and tick its checklist, and cannot reassign it or see other assignees' names beyond the organiser.
* An agent acting for a guest has the same limits.

## Constraints

Effect-TS v3; no auth SaaS lock-in beyond what <issue id="7f612e80-3332-4acf-a74c-d35db06fe4e8" label="EVE-43" href="https://linear.app/resnovas/issue/EVE-43/p14-build-identity-and-access-orgs-authorization-user-profiles-and" /> decides; whitelabel invite copy; no new dependency without approval here; ships to main with `node --run check` results pasted here.
