## Goal

A ticket holder opens the same Eventiva app the organiser uses, sees only their own tickets, shows the code at the gate even offline, fills in details and passes a ticket to someone else when the organiser allows it.

## Context

* Parent <issue id="8bd88b8d-9173-4f07-a92d-1c317836f4b2" label="EVE-76" href="https://linear.app/resnovas/issue/EVE-76/f8-ticketing-ticket-types-capacity-issuance-admissions-and-scanning" /> sections 2, 6, 9 and decision D4. One app for every role (project goal); the attendee view is a role-adapted set of screens, not a separate app.
* Holders may not have an org membership: they are external users with holder rights on their own tickets (<issue id="7f612e80-3332-4acf-a74c-d35db06fe4e8" label="EVE-43" href="https://linear.app/resnovas/issue/EVE-43/p14-build-identity-and-access-orgs-authorization-user-profiles-and" />).

## Scope

1. My tickets screen and ticket card with QR; tickets cached on device for offline display (record sync, <issue id="a1348819-43cc-4005-8e8d-a896a761af03" label="EVE-51" href="https://linear.app/resnovas/issue/EVE-51/p112-build-collaboration-yjs-for-text-and-canvas-with-record-sync-and" />) and refreshed on reconnect.
2. Actions: ticketing.transfer.offer, accept, cancel; ticket.updateHolder for own ticket when the type allows; navigation actions.
3. Transfer flow: offer to an email, recipient accepts and gets a new ticket (old one becomes transferred-out and its code stops working); blocked when the type is not transferable or within a cut-off before doors set per type (default 2 hours).
4. Attendee questions completion prompt when answers are missing.
5. Sign-in for holders by email link (through <issue id="7f612e80-3332-4acf-a74c-d35db06fe4e8" label="EVE-43" href="https://linear.app/resnovas/issue/EVE-43/p14-build-identity-and-access-orgs-authorization-user-profiles-and" /> identity), including claiming tickets bought as a guest.

## Acceptance criteria

* A holder sees only their tickets via UI, HTTP and MCP; another holder's ticket id returns not found.
* After a transfer, the old code is rejected at the next online scan and after the next device sync; the new holder's code admits.
* Tickets display with the device in airplane mode after one prior sync.
* The agent, acting for the holder, can transfer a ticket only after the holder confirms.
