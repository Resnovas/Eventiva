## Linear description

## Goal

An organisation designs list, form, board, calendar, timeline, map and gallery views for any record type, and changes the product's own screens (add a section, hide a field, move a column) in a way that survives product upgrades and stays fully visible and operable by the agent.

## Scope

1. `ViewDefinition` schema: kind, entity type, layout tree (sections, columns, field widgets, related lists, action buttons bound to existing inventory actions, dashboard panels from <issue id="1d65d374-8d06-4d69-a9c6-f3b66d565b47" label="EVE-30" href="https://linear.app/resnovas/issue/EVE-30/port-data-widgets-saved-dashboards-and-brand-kits" />), default sort and filters, visibility rules (declarative expression on the record and viewer roles).
2. A renderer in Rambo-UI terms that turns a ViewDefinition into a screen on web, iOS and Android, emitting the <issue id="91297309-acc4-4bb9-ad68-33fbc2720e5a" label="EVE-50" href="https://linear.app/resnovas/issue/EVE-50/p111-build-screen-awareness-app-state-navigation-and-the-screen" /> projection and action bindings automatically.
3. Base-screen extensibility contract: every feature-set screen declares named nodes and slots (`@slot("event.header.after")`); a lint rule fails a screen with a form or list that declares no slots.
4. `ViewPatch` ops: insert (at a slot), hide (named node), move (between slots), relabel, setDefault (make a custom view the default for a role). Patches against a node removed by an upgrade are reported in the change set preview and skipped, never crash the screen.
5. Protected nodes: feature sets mark controls `protected`; patch validation refuses ops on them with a typed `ProtectedTargetError`.
6. View designer screen (canvas on wide screens, structured list on phones) with live preview using real records the designer can see.
7. Saved personal views (filters, columns) per user, separate from org views, without studio permission.

## Acceptance criteria

* A board view of Events grouped by a custom select field works on web and Android; the agent answers "what is on this board" from the projection and moves a card via the same action as the drag (test).
* A patch inserts a custom field section into the Event screen; after a simulated base-screen upgrade that renames another node, the patch still applies and the preview lists the skipped op.
* A patch that hides `show.stopAll` is refused with `ProtectedTargetError` (test).
* An unbound control in a generated view is impossible: the renderer test fails a fixture view that names an unknown action.
* Visibility rules hide a field for crew and show it for organisers.

## Constraints

Effect-TS v3; WCAG 2.2 AA (generated views must keep heading order and labels); behind `f14-studio`; D6 (editor surfaces built in Rambo-UI; Puck only as a reference); no new dependency without approval here; ships to main per the AGENTS.md delivery exception with `node --run check` results pasted here.
