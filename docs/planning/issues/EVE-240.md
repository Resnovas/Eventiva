## Linear description

## Goal

Confirm the chosen sync engine (PowerSync with Yjs, decided on <issue id="60101c56-d4e4-4e4f-b7c8-b4c40f44ada0" label="EVE-17" href="https://linear.app/resnovas/issue/EVE-17/s4-choose-the-offline-sync-engine-for-record-edits-and-live-text-and" />) works on a real iPhone or the iOS simulator, as it already does on web, Expo web and Android.

## Context

* Decision and evidence: <issue id="60101c56-d4e4-4e4f-b7c8-b4c40f44ada0" label="EVE-17" href="https://linear.app/resnovas/issue/EVE-17/s4-choose-the-offline-sync-engine-for-record-edits-and-live-text-and" />. Android passed 6 of 6 on 2026-11-09; web and Expo web passed 7 of 7.
* iOS was never built or run, because it needs a Mac with Xcode.
* Spike app and runbook: project files `eve-s4-sync/expo/` and `eve-s4-sync/RUNBOOK-device-test.md`. Local backend: `eve-s4-sync/local-stack/` (docker compose: Postgres 16, PowerSync service 1.27.2, the Node spike backend).
* The app is an Expo SDK 58 development build (not Expo Go) using `@powersync/react-native` with op-sqlite and Yjs. lib0 needs a webcrypto provider on React Native; the spike shims it in `metro.config.js`.

## Work

1. On a Mac with Xcode, run `npx expo prebuild --platform ios` and build the spike app for a device or simulator.
2. Start `local-stack` on the same machine or network and point the app at it. iOS blocks plain HTTP by default, so allow it for the dev host only (App Transport Security exception), as `usesCleartextTraffic` does on Android.
3. Run the six runbook checks with the iOS app as bob and Expo web in a browser as alice: live sync, offline edit queue, concurrent edits, queue survives app restart, convergence, revocation.
4. While on the Mac, also open the Expo web build in Safari and run the same checks, since Safari/WebKit storage rules are the main web risk and have not been tested.
