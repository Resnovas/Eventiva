## MDT emergency action surface — clarified 15 November 2026

For **authorized control-room/MDT roles** (not automatically every active crew member), surface venue-configured show-control emergency presets and relevant hold/pause controls linked to the active incident, with conspicuous connectivity, approval state, output status and manual fallback. Actions route to the local F1 show command path via <issue id="e6838c83-005e-4ec5-bc2f-931de6cd0cb8" label="EVE-256" href="https://linear.app/resnovas/issue/EVE-256/connect-mdt-incidents-and-external-controls-to-live-show-cues-and" />; they do not issue hardware outputs directly or queue stale live commands while disconnected. Keep quick operation accessible under stress, permission-gated and auditable. Ordinary crew MDT remains least-privileged and must not gain show arming or unrestricted show control by being in MDT mode.

## Goal

A crew member on an active unit opens the same Eventiva app and gets a glanceable, gloves-friendly screen for their status, current job, messages and vehicle checks, which keeps working when signal drops.

## Context

* Parent: [EVE-71](<https://linear.app/resnovas/issue/EVE-71>) screen Crew MDT mode; journeys J3 and J4. <issue id="5c7aeec2-d49c-4028-9eca-1bc641d3618c" label="EVE-13" href="https://linear.app/resnovas/issue/EVE-13/establish-modular-core-foundations-for-database-adapters-expo-and" /> one-app rule: this is a layout of the one app chosen by role and context, not a separate app.

## Scope

1. Mode switch: when the signed-in person is a member of a unit active now on a live event, the app offers MDT mode (remembered per device); leaving the unit ends it.
2. Layout: large status buttons (one tap, undo for 5 seconds), current job card (kind, priority, location, notes, acknowledge or decline), message list with unread count, quick actions (log entry, defect, fuel), offline banner with queued count and last sync time.
3. Navigation hand-off: open the device's maps app with the job location (platform deep link, no SDK).
4. Accessibility: WCAG 2.2 AA, minimum 48 dp targets, high-contrast theme for night, screen-reader labels; works one-handed.
5. Screen-context projection: my unit, status, current job, unread messages, queued updates, connectivity.
6. Keep screen awake option while on a job; battery note in docs.

## Acceptance criteria

* On Android and web, a crew member receives an assignment, acknowledges, sets En route and On scene while offline, and the server receives all three in order on reconnect (recorded device run).
* The agent, asked by the crew member "mark us on scene", performs the same action as the button.
* axe or Lighthouse accessibility check on the web build passes with no serious issues; manual TalkBack check recorded.
* A person with no active unit never sees MDT mode.
