## Linear description

## Goal

Freelancers who are not org members can answer availability requests and offers in one tap from a link, and use the same app with a guest account if they install it.

## Context

* Slice 5 of F2 (<issue id="1c8c53a0-396b-43a7-8fb9-c138dbbc70b2" label="EVE-67" href="https://linear.app/resnovas/issue/EVE-67/f2-scheduling-and-rosters-crew-availability-shifts-offers-call-sheets" /> section 9, decision 5 recommended option a). One application per device: a guest account is the same app with a guest scope, never a separate crew app.
* Identity and guest scopes come from <issue id="7f612e80-3332-4acf-a74c-d35db06fe4e8" label="EVE-43" href="https://linear.app/resnovas/issue/EVE-43/p14-build-identity-and-access-orgs-authorization-user-profiles-and" />; links are served through the HTTP surface (<issue id="0ab161c4-ed9c-4581-86fe-91fa1f4216aa" label="EVE-46" href="https://linear.app/resnovas/issue/EVE-46/p17-build-the-http-api-streaming-and-the-typed-client-from-the-action" />).

## Scope

1. Guest identity: invite by email or phone creates a guest member scoped to assignments and requests addressed to them, across orgs if several invite them.
2. Signed single-use links for `offer.respond` and `availability.request.respond`, bound to the recipient, expiring with the offer, invalid after use or on revoke.
3. A web response page (react-native-web) with no install and no sign-in required for the single action; any other screen needs the guest sign-in.
4. Revoking guest access stops sync, invalidates links and ICS feeds at once.
5. Guest view filters: only their own assignments and the published call sheets for days they work; masked contact details for everyone else.

## Acceptance criteria

* A link accepts an offer once; a second use, a forwarded use after accept, and use after revoke all fail with typed errors and audit records.
* A guest signed in sees no other person's assignments (negative test on HTTP, MCP and sync).
* The response page passes axe with no WCAG 2.2 AA violations.
* A guest invited by two orgs sees both without data crossing between them.

## Constraints

Effect-TS v3; link tokens never logged or put in telemetry; behind flag `f2-scheduling`; no new dependency without approval here; ships to main with `node --run check` results pasted here.

## Done signal

Merged to main, security tests green, and a comment here with the check output and the token threat notes.
