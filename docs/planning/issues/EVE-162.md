## Goal

Gate crew open the Scanner screen in the same app, point the camera or a keyboard-mode scanner at a ticket and get a clear admit or reject in under a second, with entry rules per gate.

* Parent <issue id="8bd88b8d-9173-4f07-a92d-1c317836f4b2" label="EVE-76" href="https://linear.app/resnovas/issue/EVE-76/f8-ticketing-ticket-types-capacity-issuance-admissions-and-scanning" /> sections 4, 5, 6, 9. Gates are F1 Space refs (<issue id="fbcff205-decd-464a-b8ab-a1278e71fbe4" label="EVE-73" href="https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show" />) or F5 Venue entrances; gate crew are F1 TeamMembers with the Gate staff role, rostered by F2.
* This slice is online only; F8.6 adds offline. Design the scan pipeline so the same validation runs on the server and, in F8.6, on the device.

## Scope

1. CheckInList schema: admission scope, ticket types, gates, time window, re-entry rule (single, unlimited, n times, with exit scan).
2. Actions: ticketing.checkInList.create, update; ticketing.device.register, revoke; ticketing.scan.submit (device only); ticketing.checkIn.manual (always approval for agents); ticketing.checkIn.undo.
3. One pure validation function (signature, list membership, ticket status, time window, re-entry count) shared by server and device; results: admitted, rejected (void, wrong list, not yet valid, expired, already admitted, unknown, forged), warning (re-entry, holder note).
4. Pool admitted counter update through the F8.2 entity (for live in-venue counts).
5. Scanner screen: camera via Expo on native and web camera on web, keyboard-mode hardware scanner input, large result banner using shape plus text plus colour, haptic and sound, admitted counter, manual lookup by name.
6. Check-in setup screen and device registration by QR pairing code.

## Acceptance criteria

* Each rejection reason has a test from a fixture ticket.
* Online scan to result p95 under 800 ms against a staging server with 50 concurrent devices.
* A single-entry ticket scanned on two devices one second apart: first admitted, second rejected with already admitted.
* Gate staff projection never contains email, answers or order id (projection schema test).
* Agent cannot call scan.submit (inventory metadata test); manual check-in by agent requires approval.
* Screen works with screen reader labels and passes WCAG 2.2 AA contrast.
