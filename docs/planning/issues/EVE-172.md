## Linear description

## Goal

One cart and order model sells any line kind (product, ticket, stock, hire, service, fee) through a line provider contract, with orders that can be created offline and uploaded exactly once.

## Context

* Parent <issue id="7d939472-20ba-4512-b231-c0f04c05574c" label="EVE-107" href="https://linear.app/resnovas/issue/EVE-107/f9-online-and-in-person-sales-storefront-point-of-sale-orders-payments" /> sections 4, 5 and the agreed boundary at the end of section 16.
* F8 ticketing implements kind `ticket` (ticketing.hold.create, ticketing.ticket.issueForOrder, ticketing.ticket.void). F6 (<issue id="928dc098-5cc9-4586-88bb-50abbe03071a" label="EVE-63" href="https://linear.app/resnovas/issue/EVE-63/f6-warehousing-and-inventory-equipment-stock-availability-purchasing" />) implements kinds `stock` and `hire` (inventory.reservation.create, commit, release).
* Orders attach to an F1 Event and optionally a Phase and Space (<issue id="fbcff205-decd-464a-b8ab-a1278e71fbe4" label="EVE-73" href="https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show" />).

## Scope

1. `LineProvider` registration (sales.lineProvider.register at module activation, removed on disposal per <issue id="a7a66a5c-e747-4245-bc84-3232ef65a16c" label="EVE-16" href="https://linear.app/resnovas/issue/EVE-16/s3-prove-runtime-loading-and-switching-of-a-remote-module-on-expo-web" />): line kind, reserve, commit and release action names, offline mode (`online-only`, `allocation`, `deltas`).
2. Cart: create, addLine (calls the provider's reserve, stores reservation id and expiry), updateLine, removeLine (release), totals with tax from F9.1, expiry (online default 15 minutes, POS 5 minutes after last change; config via <issue id="9d08c369-bac9-4eb7-b8a7-329b5ec9bff0" label="EVE-41" href="https://linear.app/resnovas/issue/EVE-41/p12-build-app-config-settings-secrets-and-credentials" />) with a durable timer that releases reservations.
3. Order state machine: draft, placed, paid, partially refunded, refunded, cancelled. Transitions only through actions. On paid, call each line's commit; on cancel, release.
4. Client-generated UUIDv7 ids, a client order id and an idempotency key; [sales.order.place](<http://sales.order.place>) is idempotent so a replayed offline upload returns the same order.
5. Offline placement: for kinds with offline mode `deltas` or `allocation` the POS creates the order locally and syncs it; for `online-only` the line is blocked offline with a clear message.
6. Domain events on the change feed (<issue id="ee08644c-eb3c-4a46-aea7-745864ad4263" label="EVE-45" href="https://linear.app/resnovas/issue/EVE-45/p16-build-the-change-flow-domain-events-and-a-durable-resource-change" />): sales:order_placed, sales:order_paid, sales:order_cancelled with lines (net, F11 tax code id, tax amount, currency).
7. Orders list and Order detail screens with projections.

## Acceptance criteria

* A cart with one ticket line (fake provider) and one stock line (fake provider) reserves both, commits both on paid and releases both on cancel; test with fake providers implementing the contract.
* Cart expiry releases reservations exactly once, including after a runner restart (durable timer).
* Uploading the same offline order three times yields one order (idempotency test).
* An online-only line kind cannot be added to an offline cart; typed error.
* Change feed events match the schema F11 consumes.

## Constraints

Effect-TS v3 house rules; no zod; money in integer minor units; behind the `f9-sales` flag; no new dependency without Jonathan approving it on this issue; ships to main per the AGENTS.md delivery exception with `node --run check` results pasted here.
