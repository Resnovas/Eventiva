## Goal

Every action, agent turn and protocol call is traced through OpenTelemetry, and product analytics, errors and flags go through a port with PostHog as the default adapter.

## Context

* Phase-1 step 5 of the S2 capability map. Upstream reference at 6b5cf68: `observability/`, `tracking/` (includes `posthog-exception.ts`), `packages/otel` (replace with `@effect/opentelemetry`).

D4: vendor-neutral, easy to switch.

## Scope

1. `@effect/opentelemetry` layer with OTLP export configured by `Config`; no vendor SDK in core.
2. Automatic spans for action calls (name, principal kind, outcome, duration), agent turns, model calls (tokens, model, provider) and protocol requests; secret fields never in attributes.
3. A tracking port (events, identify, exceptions, feature flags) with a PostHog adapter in an integration module and a no-op default.
4. Failure context for agent runs (upstream `observability/` failure context) attached to the span.

## Acceptance criteria

* An in-memory exporter test asserts the span tree for one action called by the agent: turn, model call, tool call, action.
* Swapping the tracking adapter to no-op changes no other code (test).
* No Sentry, LaunchDarkly or Amplitude import anywhere (lint).
