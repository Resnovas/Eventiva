## Goal

The agent keeps relationships moving: it summarises any contact with sources, suggests the next follow-up, spots gaps before an event, and never acts on people outside the user's permissions or without the approvals in the parent.

## Scope

1. Action `crm.relationship.summarise` (party; returns summary text plus cited timeline entry ids; online only, states the offline limitation).
2. Action `crm.followUp.schedule` (creates an F3 Task linked to the party and opportunity).
3. Daily suggestion run per tenant, each suggestion an item the user accepts or dismisses (`crm.suggestion.accept` / `dismiss`): stale opportunity (no interaction for N days, default 14, tenant setting); event in the next 7 days with no venue contact; new duplicate candidates; privacy request due within 7 days.
4. Agent skill descriptions for the CRM actions (written for the agent, per <issue id="dc89a6af-338c-417b-a352-80cbfb05ec1e" label="EVE-40" href="https://linear.app/resnovas/issue/EVE-40/p11-build-the-action-contract-and-inventory-in-effect-schema" />), and screen projections that let the agent answer "what am I looking at" on every F4 screen.
5. Suggestion surface: a Suggestions panel on the CRM home and on detail pages, each control bound to an action.

## Acceptance criteria

* Tests: a suggestion never runs its action until accepted; a user without `crm:read` gets no CRM suggestions; summaries include only entries the user can read, with every claim mapped to a cited id.
* Evaluation set of 20 relationship questions with expected cited entries passes at 18 or more (dataset committed; linked to <issue id="bef04957-8bec-479e-85ee-5880dfc9fc8c" label="EVE-29" href="https://linear.app/resnovas/issue/EVE-29/port-agent-evaluations-linked-to-posthog-datasets" /> when available).
* `node --run check` green.
