## Linear description

## Goal

Sites show live Eventiva data (schedules, tickets, products, listings, maps) that updates without republishing, one template page can serve every Event, and public forms land submissions in the right records safely.

## Context

* Parent: <issue id="d6f1d3a2-12a8-474b-abae-aa29b394d45d" label="EVE-111" href="https://linear.app/resnovas/issue/EVE-111/f14-website-builder-and-in-app-customisation" /> sections 4 (`forms.*`), 5 (Page binding, block bindings, FormDefinition, FormSubmission), 8 (`BotChallenge` port) and 11 (personal data, consent).
* F1 names from <issue id="fbcff205-decd-464a-b8ab-a1278e71fbe4" label="EVE-73" href="https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show" /> section 5: the public schedule comes from Event (anchor), Phase and Segment where `Segment.audience = public`, in a published RunOfShow. F14 reads these through F1's public read actions and never defines them.
* Bindings store a read action and its input, never a snapshot (the <issue id="1d65d374-8d06-4d69-a9c6-f3b66d565b47" label="EVE-30" href="https://linear.app/resnovas/issue/EVE-30/port-data-widgets-saved-dashboards-and-brand-kits" /> panel rule), so data re-runs under the viewer: for a public site the viewer is the anonymous principal, which only sees fields the owning feature set marks public.
* Ticket (F8), product and checkout (F9), directory (F5) and site map (F10) blocks are thin wrappers over those sets' public actions; if a set's public action does not exist yet, its block ships disabled with a placeholder.

## Scope

1. Binding model: `{ action, input, fields }` with input values that may reference the page context (for a collection page, the current record id). Validation at edit time that the action is a public-safe read (side-effect class read, permission available to the anonymous principal).
2. Collection pages: a Page binding of entity type plus filter plus slug field generates one URL per record (for example `/events/{slug}` for every published Event in the site's EventSeries); 404 for records that stop matching.
3. Data blocks: event header, public schedule (Phase and public Segment, grouped by day and Space), countdown, ticket selector (F8), product grid (F9, links into F9 checkout), directory listing and profile (F5), site map (F10), list of any custom record type marked public (F14.2), single field value.
4. Forms: `forms.define` with fields (from the target action's input schema or custom fields), a target action (for example F4 `contacts.create`, or `records.custom.create`), consent text and purpose, retention days, notifications (<issue id="9aae6a50-4a43-4327-ae6a-51d18bc69b35" label="EVE-24" href="https://linear.app/resnovas/issue/EVE-24/port-notifications-messaging-channels-and-transactional-email" />), and an optional automation trigger (F14.5).
5. `forms.submit` for the anonymous principal: Effect Schema validation, rate limit per IP and form, `BotChallenge` port check, idempotency key, then the target action runs as the form's service principal with only that permission; submissions stored with retention and erasure.
6. `forms.submissions.list/export/delete` with pii masking; export is `confirm` for the agent.
7. Caching: data blocks render server-side with a short cache and revalidate on change-feed events (<issue id="ee08644c-eb3c-4a46-aea7-745864ad4263" label="EVE-45" href="https://linear.app/resnovas/issue/EVE-45/p16-build-the-change-flow-domain-events-and-a-durable-resource-change" />) for the bound records.

## Acceptance criteria

* Changing a public Segment time in the RunOfShow updates the published schedule within one minute with no republish; a Segment with audience crew never appears (test).
* One collection page serves three Events with correct URLs; unpublishing an Event returns 404 for its page.
* A form creates an F4 contact; a bot submission without a valid challenge and a burst over the rate limit are both refused (test); a submission is deleted when its retention expires.
* A binding to a write action or a non-public read is refused in the editor with `BindingNotPublic`.

## Constraints

Effect-TS v3; WCAG 2.2 AA for every block and form (labels, errors announced); behind `f14-sites`; `BotChallenge` vendor needs approval on this issue (proposal: a privacy-friendly challenge, chosen when this slice starts); no new dependency without approval here; ships to main per the AGENTS.md delivery exception with `node --run check` results pasted here.
