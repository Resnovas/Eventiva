## Linear description

## Goal

A production manager states what crew an Event needs (role, count, times, place) per Phase, and Eventiva turns that into concrete shifts that can be filled.

## Context

* Slice 2 of F2 ([EVE-67](<https://linear.app/resnovas/issue/EVE-67/f2-scheduling-and-rosters-crew-availability-shifts-offers-call-sheets>)). Attaches to F1 entities (<issue id="fbcff205-decd-464a-b8ab-a1278e71fbe4" label="EVE-73" href="https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show" /> section 5) Event, Phase, Department, Space and RunOfShow by id; F2 does not redefine them. Shifts must be readable per TeamMember and Phase so F1 `itinerary.generate` can build ItineraryItem kind `shift`.
* Shifts are [EVE-33](<https://linear.app/resnovas/issue/EVE-33/port-scheduling-primitives-for-availability-bookings-and-rosters>) booking slots on a person resource, so conflicts with vehicles (F7) and kit (F6) use one engine.
* Run of show changes arrive through the change feed ([EVE-45](<https://linear.app/resnovas/issue/EVE-45/p16-build-the-change-flow-domain-events-and-a-durable-resource-change>)).

## Scope

1. Tables CrewRequirement (eventId, phaseId?, departmentId?, spaceId?, roleId, count, times, qualifications) and Shift; `org_id` and Event scope on every row. A read action `shift.listForItinerary` (by Event, TeamMember, Phase) for F1.
2. Actions `requirement.create`, `requirement.update`, `requirement.delete` (agent confirm), `requirement.fromRunOfShow` (drafts requirements from a Run of show and a crew template; agent confirm), `shift.generate` (split a requirement into shifts by count and split rules such as maximum shift length), `shift.update`, `shift.cancel` (approval always when assigned).
3. Requirement templates per org (for example "Standard load-in: 4 riggers, 2 lighting, 1 crew chief").
4. When a Phase moves, a domain event marks affected shifts `needs_review` rather than moving them silently.
5. Conflict rule: a count decrease below the number already assigned is rejected at sync with a typed error.
6. Screen: Event staffing with filled versus needed per Phase, projection and bindings per [EVE-67](<https://linear.app/resnovas/issue/EVE-67/f2-scheduling-and-rosters-crew-availability-shifts-offers-call-sheets>) section 6.

## Acceptance criteria

* From a Run of show with three Phases, `requirement.fromRunOfShow` drafts requirements matching the template; applying it creates shifts with correct times in the venue timezone.
* Moving a Phase by 2 hours flags its shifts `needs_review` and emits one change record.
* Decreasing count below assigned fails offline-replay with `RequirementBelowAssigned`.
* The Event staffing screen passes the unbound-element check.
