## Linear description

## Goal

Define a low-friction, trustworthy supplier inventory onboarding and product-catalogue enrichment strategy so a new supplier can search for a manufacturer/model by name, find the correct technical reference quickly, and bulk-load their existing stock without rebuilding every product record manually.

**Status: deferred product research / specification discovery only.** Capture the challenge and return to it after foundational module and platform design. Do not start scraping, importing, implementation or external supplier outreach from this ticket.

## Context

Eventiva's F6 product catalogue and supplier inventory feed technical equivalence (<issue id="f08bafe4-f32d-4906-9e87-5d69df56d6a0" label="EVE-124" href="https://linear.app/resnovas/issue/EVE-124/f58-build-quotes-quote-comparison-and-the-acceptance-handoff-to-the" />), supplier recommendations (<issue id="b22fbb0d-100b-47a3-8c32-eeacadc4c9fe" label="EVE-66" href="https://linear.app/resnovas/issue/EVE-66/f5-directory-and-marketplace-vendor-venue-and-professional-listings" />), and supplier quote selection (<issue id="03bd23d1-9da5-4272-8f2e-0b0bf4f7f846" label="EVE-119" href="https://linear.app/resnovas/issue/EVE-119/f57-build-cross-tenant-enquiries-rfps-and-private-message-threads" />). The shared reference product/model specification must be distinct from tenant-private supplier stock, quantities, pricing, reservations and ownership. Accurate product identity and evidence will matter before useful automatic equipment matching can be trusted. Prior plans for supplier-selectable catalogue records and controlled uploads are in <issue id="eaa9fbf7-7a3c-4c1c-9470-a76edd5316ff" label="EVE-81" href="https://linear.app/resnovas/issue/EVE-81/f61-build-the-equipment-catalogue-products-tracking-modes-and-kits" /> and its linked decisions D6-7/D6-8/D6-9.

The key adoption hurdle: when a supplier types a brand, product name or model, they should normally find the correct existing product and its relevant manufacturer specifications immediately, rather than spending hours manually recreating equipment descriptions and dimensions. The user suggested significant catalogue research, data acquisition/web scraping (possibly Firecrawl or similar), interviews/surveys of supplier inventory tools, CSV/export-based import, and efficient team-based manual/bulk entry. Supplier-account setup, KYC and payment onboarding (e.g. Stripe connected-account requirements) are separate, later work - do not expand this ticket into payments onboarding.

## Research and design questions to resolve when resumed

1. **Product reference coverage and search.** Identify priority live-event equipment categories and manufacturers/models, canonical identifiers, version/variant/SKU distinctions, synonyms, search-as-you-type relevance, typos and duplicate/mislabelled records. Define realistic coverage and search-confidence targets, not an unsupported guarantee that all products exist.
2. **Trusted data acquisition.** Investigate manufacturer catalogues, datasheets, published APIs, licensed feeds, distributors and appropriate crawling/extraction approaches (Firecrawl is a candidate, not a chosen dependency). Assess source permission/terms, robots directives, copyright/database rights, freshness, update frequency, provenance and cost. Prefer authoritative manufacturer information where feasible; do not treat arbitrary scraped sales copy as verified technical evidence.
3. **Normalisation and validation.** Category-specific typed specifications, units, dimensions, interfaces, intended uses, accessories, model revisions, conflicting sources, evidence versioning, confidence/verification, duplicate detection, controlled supplier corrections and reconciliation. Avoid silently merging different models.
4. **Supplier ecosystem discovery.** Survey or interview representative rental/production suppliers to learn which inventory/asset/hire systems they use, what export formats and fields are available, whether APIs/connectors exist, and common data-quality issues. Do not assume any one vendor or format dominates before research.
5. **Bulk import experience.** Define CSV (and other justified exports) upload, template/sample files, column mapping, unit transforms, preview/validation, model matching, duplicates, missing values, supplier SKU mapping, kit/asset/serial versus bulk-stock distinctions, staged confirmation, partial errors, undo/idempotent re-import and import audit. Permit manual, collaborative team-assisted entry and streamlined bulk edits, not only file upload.
6. **Onboarding usability.** Compare quick find-and-add, guided bulk import, supplier self-service and multiple team-member workflows. Separate shared product references from supplier-owned quantities and calendar/availability. Track import completeness and confidence without blocking quotations when specifications remain incomplete.
7. **Agent-native parity, privacy and architecture.** Ensure all catalogue search/import/review actions are available to authorised users and agents through the common Effect-based action layer. Preserve F6 private inventory and <issue id="b22fbb0d-100b-47a3-8c32-eeacadc4c9fe" label="EVE-66" href="https://linear.app/resnovas/issue/EVE-66/f5-directory-and-marketplace-vendor-venue-and-professional-listings" /> D5-16 detailed/dates-only/hidden publication controls and explicit recommendation matching opt-out. No default shared-model training of supplier-private records.

## Validation / deliverables for this future planning ticket

* A cited source/licensing and acquisition feasibility matrix, with sample verified manufacturer records across a small representative equipment set; explain coverage gaps and conflict handling.
* A supplier discovery findings summary identifying actual commonly used inventory tools, viable export formats and prioritised import patterns.
* A documented candidate data model and provenance/verification workflow showing reference product vs supplier stock identity, quantity, kit, reservation and quote mapping.
* Reviewed user journeys for search-add, team/bulk manual entry and CSV import, including invalid/duplicate rows, re-import and rollback scenarios.
* An actionable phased implementation specification with explicit acceptance metrics to be agreed from evidence (e.g. representative search hit quality, matching precision and import success), dependencies, risks and cost estimates. This planning ticket is complete when these decisions are documented and reviewed, **not** when a scraper or importer has been built.

## Out of scope

Do not execute research, scraping, supplier survey, ingestion, imports, code changes, model training, user onboarding/KYC, Stripe setup, or deployment at this stage. No assumption that every manufacturer permits scraping or that Firecrawl is definitely required. No premature importer/vendor selection.

## Escalation / decisions on resumption

Return for decisions on initial categories and manufacturer coverage, licensed/allowed data sources, target inventory software integrations, privacy and verification ownership, budget constraints, and what import quality is acceptable. Stop if proposed crawling conflicts with legal terms, if source identity cannot be verified, or if matching risks conflating supplier-private stock with public model reference data.
