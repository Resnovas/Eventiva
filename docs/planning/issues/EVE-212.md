## Goal

The agent acts as a ticketing assistant across every surface: it drafts setups, watches sales and doors, raises the right alerts and never takes a risky step without the user's approval.

## Scope

1. Ticketing skill text for the agent (what each action is for, typical sequences, approval rules) generated from inventory descriptions plus a short hand-written guide.
2. Watchers as durable scheduled runs per Event: capacity at 80 and 95 percent, pace behind target, holds blocking sales, missing attendee details 48 hours before doors, devices unsynced over 10 minutes during doors, duplicate-entry and void-admit alerts. Each posts a suggestion in the organiser's agent thread with one-tap actions, never acting alone.
3. ticketing.gateBriefing.generate: a document for an admission scope with lists, gates (F1 Space), expected arrivals by hour, re-entry rules, rostered gate crew (F2) and escalation contacts.
4. End-to-end approval tests across UI, MCP and ACP for every action marked confirm or always.

## Acceptance criteria

* Scripted-model test: "set up tickets for the festival, 3 days, 2,000 per day, early bird until March" produces draft types and pools per day Phase and asks before publishing.
* Each watcher fires once per threshold crossing (no repeats on restart) in a durable-run test with a runner restart.
* Every confirm or always action is refused without approval when called by an agent through MCP and ACP.
* The gate briefing for a fixture event matches the check-in lists and roster.
