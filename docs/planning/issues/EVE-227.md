## Linear description

## Goal

An organiser gets a complete, on-brand, accessible draft site from a short brief and an Event in minutes, and can change any page by telling the agent what they want, always reviewing a diff before anything goes live.

## Context

* Parent: <issue id="d6f1d3a2-12a8-474b-abae-aa29b394d45d" label="EVE-111" href="https://linear.app/resnovas/issue/EVE-111/f14-website-builder-and-in-app-customisation" /> sections 4 (`sites.generate`, `pages.generate`, `sites.translations.generate`), 7 (agent behaviour) and 10 (success metric: drafts accepted with under 20% of blocks changed).
* The agent edits only through `pages.blocks.*` and `pages.*` (<issue id="3deaef52-8db8-490c-8143-b293ab5656a8" label="EVE-52" href="https://linear.app/resnovas/issue/EVE-52/p18a-build-the-agent-turn-loop-with-actions-as-tools" /> tools), so generation is a planned batch of ordinary actions in one change record with one undo, not a separate code path.

## Scope

1. `sites.generate`: input brief, source records (an Event and its public data from F1, the org profile, optional F5 listing), template (optional), locales; output a draft site (pages, menus, blocks with bindings to the source records rather than copied text where data exists) plus a GenerationReport (what was created, what needs human input such as missing images).
2. `pages.generate`: instruction plus scope (selected block or page from the editor projection); output a proposed diff shown in the editor; accept applies it as one change record, reject discards it.
3. Generation rules: only registered block types with valid props; headings in order; alt text for every image (generated, flagged for review); brand kit colours only; placeholder images from the org's media first; no invented facts about the Event (dates, prices, venue come from bindings).
4. Image generation is out of this slice unless an image engine is already approved; otherwise use media library and placeholders.
5. `sites.translations.generate`: per-locale draft text for every text prop, flagged as machine-translated until a person edits or approves it.
6. Eval fixtures: five briefs with expected structure checks (page count, blocks bound to source data, accessibility checks pass), run through <issue id="bef04957-8bec-479e-85ee-5880dfc9fc8c" label="EVE-29" href="https://linear.app/resnovas/issue/EVE-29/port-agent-evaluations-linked-to-posthog-datasets" /> when available, else recorded-model tests.

## Acceptance criteria

* From "two-day food festival in Leeds, family friendly, sell early bird tickets" plus an Event, the agent produces a draft site whose schedule and ticket blocks are bound to that Event, which passes the F14.10 publish checks without edits (recorded-model test).
* "Make the hero shorter and add a FAQ about parking" on a page produces a diff; accepting it is one undo step.
* With no connection, `sites.generate` returns `OfflineUnavailable` and the UI says so.
* Translations are marked machine-translated until approved.
