## Linear description

## Goal

An organiser starts a new event from a past one or a saved template (a tour date, a yearly festival, a standard conference) and gets its phases, departments, plans, cue lists and run-of-show skeleton with every date shifted, in one step.

## Context

* Parent: <issue id="fbcff205-decd-464a-b8ab-a1278e71fbe4" label="EVE-73" href="https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show" /> sections 4 (`event.clone`, `event.saveAsTemplate`), 5 (EventTemplate, EventSeries production package).
* For a tour, the EventSeries production package is a template every date in the series starts from.

## Scope

1. Table `event_template` (org-wide: name, snapshot of selected parts, day-0 relative offsets for all times).
2. Actions: `event.saveAsTemplate` (choose parts: phases, spaces, departments, documents, plans, cue lists, run of show, requirements), `event.clone` (from an event or a template, new day 0, new venue optional), `template.list`, `template.delete`.
3. Cloning rules: ids are new; references to other sets (F4 parties, F5 venue, F6 products) are kept; people (TeamMembers), itineraries, show runs, sign-offs and published versions are never copied; rigging sign-offs start void.
4. Large clones run as a durable job (<issue id="a626308a-598f-41ba-accd-4004cbbd9932" label="EVE-54" href="https://linear.app/resnovas/issue/EVE-54/p18c-build-durable-agent-runs-on-effect-cluster-and-workflow" /> pattern) so a closed app does not leave a half-copied event; the job is idempotent on retry.
5. Agent: "make next year's festival from this one, two weeks later, without the second stage" through the same actions.
6. Screen: a clone dialog on the Event overview and a Templates list, with projections and bound controls.

## Acceptance criteria

* Cloning a 3 phase, 2 space event with a run of show and 2 cue lists shifts every time by the chosen offset, including across a daylight-saving change.
* No TeamMember, itinerary, show run or sign-off is copied; sign-offs on the copy are void.
* Interrupting a clone and retrying produces exactly one complete event.
* Screen passes the unbound-control check and axe.

## Constraints

Effect-TS v3 house rules (date shifting is pure TypeScript); every operation is an inventory action with one permission check, audit and change record; UI from Rambo-UI, WCAG 2.2 AA; behind PostHog flag `f1-events-core`; no new dependency without Jonathan approving it on this issue; whitelabel ASCII copy; people docs and ai-docs in the same commit; ships to main with `node --run check` results here.
