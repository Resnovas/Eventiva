## Goal

The agent watches stock for the user and brings ready-to-approve fixes (hire in, buy, schedule an inspection, chase a return) before a problem reaches an event.

The agent can never release a failed safety inspection.

## Scope

1. Shortage responder: on `inventory:shortage_detected`, compute options (substitute in category, transfer between warehouses, sub-hire F6.9, purchase F6.8) ranked by cost then lead time, draft the best one, and post a suggestion to the event owner with one-tap approve.
2. Inspection planner: daily, list assets with inspections due before their next reservation's out date (F6.7) and propose maintenance jobs before each out date.
3. Reorder assistant: daily, run `purchasing.reorder.evaluate` and propose draft requests grouped by supplier.
4. Overdue returns: when return due has passed and assets are still at an event-site or vehicle location, draft discrepancies and a message to the crew lead (<issue id="9aae6a50-4a43-4327-ae6a-51d18bc69b35" label="EVE-24" href="https://linear.app/resnovas/issue/EVE-24/port-notifications-messaging-channels-and-transactional-email" />).
5. Prompted skills and descriptions for every F6 action so the agent can answer: "what am I short for Saturday", "where is case 0412", "which hoists are due this month", "reorder haze fluid", "hire in what we are missing".
6. Each suggestion records `inventory_agent_suggestion_accepted` or rejected for the success metric.

## Acceptance criteria

* A reservation that causes a shortage produces one suggestion within one change-feed cycle, with the draft prefilled; approving it sends the sub-hire or order; rejecting it writes nothing.
* The planner proposes an inspection for a hoist due 3 days before its next out date and none for assets not reserved.
* The five example requests above each complete in an eval (<issue id="bef04957-8bec-479e-85ee-5880dfc9fc8c" label="EVE-29" href="https://linear.app/resnovas/issue/EVE-29/port-agent-evaluations-linked-to-posthog-datasets" /> when available, otherwise `@effect/vitest` scripted turns) using only inventory actions, stopping at every approval.
* A user without purchasing permission never receives a purchase suggestion.
