## Linear description

## Goal

The staging and video teams plan risers, set pieces and screens, and pre-program what each screen shows in every segment and on every cue, so content is ready and checked before the show.

## Context

* Parent: <issue id="fbcff205-decd-464a-b8ab-a1278e71fbe4" label="EVE-73" href="https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show" /> sections 4, 5 (ScreenSurface, ScreenContent), 6, 13 (no media server replacement).
* Staging elements and screens are DesignElements on the plan (F1.6) with kinds `riser`, `set`, `screen`. Media files come through <issue id="8d8d301b-d679-4dac-95bb-c24889179cd0" label="EVE-25" href="https://linear.app/resnovas/issue/EVE-25/port-files-private-attachments-artifacts-and-document-import" />. Playback of content live is a cue that F1.13 sends to a media server; Eventiva does not play video itself.

## Scope

1. Tables `screen_surface` (element_id, pixel width and height, aspect, input name, processor notes) and `screen_content` (surface_id, segment_id or cue_id, media ref, playback notes such as loop, hold, fade).
2. Actions: `screen.addSurface`, `screen.updateSurface`, `screen.assignContent`, `screen.removeContent`, `screen.checkContent`.
3. `screen.checkContent`: flags media whose resolution or aspect does not match its surface, segments with no content on a surface that should have some, and missing files.
4. A content grid view: segments down, surfaces across, each cell the assigned media thumbnail, readable offline once files are cached.
5. Agent: assigns content from a brief ("holding slide on both side screens between panels"), runs the check, never deletes media.
6. Screen: Screens (surface list, content grid, check results) with projection and bound controls; staging uses the plan canvas.

## Acceptance criteria

* A 1920 by 1080 file on a 3840 by 1080 surface is flagged as an aspect mismatch.
* The content grid works offline after files are cached on the device.
* Assigning content to a cue makes it available to F1.13 as the cue's target payload.
* Screen passes the unbound-control check and axe.

## Constraints

Effect-TS v3 house rules; every operation is an inventory action with one permission check, audit and change record; UI from Rambo-UI, WCAG 2.2 AA; behind PostHog flag `f1-production-plans`; reading image dimensions uses what <issue id="8d8d301b-d679-4dac-95bb-c24889179cd0" label="EVE-25" href="https://linear.app/resnovas/issue/EVE-25/port-files-private-attachments-artifacts-and-document-import" /> provides, no new dependency without Jonathan approving it on this issue; whitelabel ASCII copy; people docs and ai-docs in the same commit; ships to main with `node --run check` results here.
