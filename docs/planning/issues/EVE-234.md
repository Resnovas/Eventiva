## Linear description

## Goal

Organisations start from good event, venue and vendor templates, keep every site on brand through their brand kit, and save their own sites as reusable templates for the next event.

## Context

* Parent: <issue id="d6f1d3a2-12a8-474b-abae-aa29b394d45d" label="EVE-111" href="https://linear.app/resnovas/issue/EVE-111/f14-website-builder-and-in-app-customisation" /> sections 4 (`templates.*`), 5 (Template) and 13 (no paid marketplace).
* Brand kits (colours, type, logo) come from <issue id="1d65d374-8d06-4d69-a9c6-f3b66d565b47" label="EVE-30" href="https://linear.app/resnovas/issue/EVE-30/port-data-widgets-saved-dashboards-and-brand-kits" /> and feed Rambo-UI theming; site blocks read only theme tokens, never raw colours, so switching kit restyles a site and keeps contrast checks valid.
* F5 directory profiles use a locked template where only some blocks are editable by the vendor or venue.

## Scope

1. Template = a site snapshot without tenant data: pages, block trees with bindings expressed as slots ("the site's Event") rather than record ids, menus, SEO defaults, required brand tokens.
2. Platform templates at launch: single-day event, multi-day festival, conference with tracks, venue, vendor profile, organisation home. Each passes the F14.10 publish checks with sample data.
3. `templates.apply`: create a draft site from a template, binding its slots to chosen records (for example an Event) and the org's default brand kit.
4. `templates.saveFromSite`: org-scoped template from an existing site, stripping record ids into slots and removing form submissions and personal data.
5. Theme tokens: map brand kit to Rambo-UI tokens (colour roles, type scale, radius, spacing); a contrast check runs when a kit is applied and warns before publish.
6. Locked templates for F5 profiles: per-block `editableBy` (owner org, listed vendor) honoured by `pages.blocks.*`.
7. Template gallery screen with live previews.

## Acceptance criteria

* Applying the festival template to an Event yields a draft that passes publish checks with no edits.
* Switching brand kit restyles every block; a kit with failing contrast shows the warning and blocks publish until fixed.
* A saved org template applied to a second Event binds to it with no reference to the first Event's id (test).
* A vendor can edit only unlocked blocks on their F5 profile page (test on UI and MCP).

## Constraints

Effect-TS v3; WCAG 2.2 AA; behind `f14-sites`; template content whitelabel and ASCII only; no new dependency without approval here; ships to main per the AGENTS.md delivery exception with `node --run check` results pasted here.
