## Linear description

## Goal

Managers and workers run regular reviews, set and track goals, and give feedback after each event, so performance history sits with the worker record and informs future crewing, for employees and for freelancers who work repeatedly.

## Scope

1. Tables ReviewTemplate (versioned: sections, rating scales, questions), ReviewCycle (name, audience filter, period, deadlines), Review (worker, reviewer, status draft, self-review, manager review, calibrated, shared, acknowledged), Goal (owner, description, measure, due, progress, status, optional link to F3 tasks), Feedback (giver, subject worker, optional F1 Event, ratings, comment, visibility: private to HR and manager, or shared with the worker).
2. Actions: `hr.reviewTemplates.create` / `.update`; `hr.reviewCycles.create` / `.launch` (confirm; creates one Review per worker in the audience); `hr.reviews.submitSelf`, `.submitManager`, `.calibrate` (HR, confirm), `.share` (confirm), `.acknowledge` (worker only, human-only); `hr.goals.create`, `.update`, `.updateProgress`, `.close`; `hr.feedback.give`, `hr.feedback.list`; `hr.eventFeedback.request` (asks the crew chief of an F1 Event for short feedback on each TeamMember after the Event ends).
3. Permissions: worker sees own reviews once shared and own goals; manager sees direct reports; HR sees all; peers can give feedback but never read it; supplying agencies see nothing. Grants hr:reviews:*, hr:goals:*, hr:feedback:\*.
4. Review content is personal data: masked in projections for anyone without access, excluded from telemetry and agent memory (<issue id="636f7592-553b-41f2-adb0-9a336d0188e3" label="EVE-116" href="https://linear.app/resnovas/issue/EVE-116/f132-build-the-sensitive-profile-with-field-masking-reveal-audit-and" /> rules), included in the subject export and covered by a retention default (6 years after the engagement ends, configurable).
5. Screens `hr.reviews` (cycle board), `hr.review` (collaborative editor with sections), `me.reviews`, `me.goals`, with projections and every control bound to its action.
6. Agent: drafts a review summary from goals, feedback and post-event ratings for the manager to edit; suggests goals; chases overdue reviews. It never submits a manager review or acknowledges a review for anyone (human-only), and never writes ratings itself. Behind flag `hr-agent-review-drafting`, default off.
7. Repeat-freelancer view: average post-event ratings and the last three feedback comments visible to crew coordinators only if the tenant enables it (setting, default off), so F2 can prefer well-rated crew without exposing review text.
8. Telemetry: `hr_review_cycle_launched`, `hr_review_submitted`, `hr_review_shared`, `hr_goal_closed`, `hr_feedback_given` (no content).

## Acceptance criteria

* Launching a cycle for 20 workers creates 20 reviews; self and manager reviews submit; HR calibrates and shares; the worker acknowledges; every step is audited.
* A peer who gave feedback cannot read it back, and a crew coordinator cannot read any review text (negative tests on UI, HTTP, MCP and ACP).
* After an F1 Event ends, the crew chief receives one feedback request per TeamMember; submitted ratings appear on each worker's record.
* The agent drafts a summary that the manager edits, and is refused with `HumanOnlyAction` when asked to submit or acknowledge.
* No review text appears in spans, events or agent memory in a full test run.
