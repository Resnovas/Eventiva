## Goal

The owner, the event manager and the external accountant each get the standard financial reports and a per-event P and L from the same ledger, with every figure traceable to journal lines.

## Scope

1. Report engine over posted journals with filters (date range, comparison period, dimensions: F1 Event, EventSeries, Phase, Department, custom).
2. Reports: trial balance, profit and loss, balance sheet, cash flow (indirect), aged receivables, aged payables, VAT detail, event P and L (revenue, direct cost, margin, budget vs actual by Phase), event series comparison.
3. Drill-down from any figure to journal lines and source documents.
4. Exports: CSV per report, a journal CSV, and an accountant pack (trial balance, ledgers, VAT detail, document index) as one archive. Package sync to external accounting tools is not built here; `AccountingExportPort` exists with the CSV adapter only.
5. Actions: `accounting.report.run`, `accounting.report.save`, `accounting.export.run`.
6. Screens: reports viewer and finance home tiles (via <issue id="1d65d374-8d06-4d69-a9c6-f3b66d565b47" label="EVE-30" href="https://linear.app/resnovas/issue/EVE-30/port-data-widgets-saved-dashboards-and-brand-kits" /> widgets). Projections include visible rows so the agent explains what the user sees.
7. Agent: answers questions with figures from `report.run`, always citing the report and filters it used.

## Acceptance criteria

* On the seeded tenant, the balance sheet balances and P and L net profit equals the retained earnings movement.
* Event P and L for a seeded F1 Event matches a hand-computed fixture.
* An event manager sees the P and L of their own events and is denied the business P and L (permission test).
* Report of 1 million journal lines returns in under 2 seconds on the CI Postgres (performance budget test).

## Constraints

Effect-TS v3; no new dependency; amounts never in telemetry; flag `f11-accounting`; ship to main with `node --run check` results pasted here.
