## Linear description

## Goal

A UK VAT-registered tenant prepares its VAT return from the ledger, sees how every box was built, and a named person submits it to HMRC from Eventiva.

## Context

* Parent <issue id="158ba369-976e-47ea-9f86-a8df608cb4d0" label="EVE-69" href="https://linear.app/resnovas/issue/EVE-69/f11-accounting-ledgers-invoices-bills-event-budgets-and-tax" /> sections 4, 8 and 11. Decision D2 on <issue id="158ba369-976e-47ea-9f86-a8df608cb4d0" label="EVE-69" href="https://linear.app/resnovas/issue/EVE-69/f11-accounting-ledgers-invoices-bills-event-budgets-and-tax" />: UK VAT with MTD submission first.
* F11 owns tax codes; F9 and F6 reference F11 tax code ids (agreed 2026-11-01). Until this lands, F11.4 uses a seeded set.
* HMRC MTD VAT API: OAuth user-restricted access, obligations, submit return, view return, liabilities and payments, plus mandatory fraud prevention headers. Production use needs the software to be recognised by HMRC; that application is an outward step Jonathan approves before it starts. The sandbox needs only a developer account.

## Scope

1. `TaxCode` (rate, scheme: standard, reduced, zero, exempt, outside scope, reverse charge, EC and NI goods where they still apply; effective from and to), seeded and editable. Schemes supported: standard accrual and cash accounting; flat rate scheme is a later slice.
2. `TaxReturn` built from posted journals for a period: the 9 boxes, each with drill-down to journal lines; adjustments as journals, never edits.
3. `TaxFilingPort` with an HMRC MTD VAT adapter (integration package): obligations, submit, view, fraud prevention headers gathered from the client device and server.
4. Actions: `accounting.tax.code.*`, `accounting.tax.obligation.list`, `accounting.tax.return.prepare` / `submit` (approval always; the permission is person-only, never delegable to an agent), `accounting.tax.return.view`.
5. Screen: tax returns with box drill-down and a declaration step. Projection includes boxes and status.
6. Agent: prepares the return and explains each box on request; cannot submit.

## Acceptance criteria

* A fixture quarter produces boxes that match a hand-computed sheet to the penny.
* Submission to the HMRC sandbox succeeds and the receipt is stored immutably; a resubmission for the same period is blocked.
* The fraud prevention header validator in the sandbox reports no errors for web, iOS and Android clients.
* An agent session holding a finance admin delegation cannot call `accounting.tax.return.submit` (denied test on every surface).

## Constraints
