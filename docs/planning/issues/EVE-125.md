## Linear description

## Goal

An event manager sets a budget per F1 Phase, edits it offline, gets it approved, and always sees budget, committed and actual side by side.

## Context

* Parent [EVE-69](<https://linear.app/resnovas/issue/EVE-69/f11-accounting-ledgers-invoices-bills-event-budgets-and-tax>) sections 4 to 7. Uses F1 Event (anchor), EventSeries, Phase and Department by id as dimension values; does not redefine them (names fixed in <issue id="fbcff205-decd-464a-b8ab-a1278e71fbe4" label="EVE-73" href="https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show" /> section 5). F1 EquipmentRequirement (event, phase, department, F6 catalogue ref, quantity, dates) feeds forecast equipment cost.
* Record sync and conflict rules from [EVE-51](<https://linear.app/resnovas/issue/EVE-51/p112-build-collaboration-yjs-for-text-and-canvas-with-record-sync-and>) and the engine chosen in [EVE-17](<https://linear.app/resnovas/issue/EVE-17/s4-choose-the-offline-sync-engine-for-record-edits-and-live-text-and>); screen awareness from [EVE-50](<https://linear.app/resnovas/issue/EVE-50/p111-build-screen-awareness-app-state-navigation-and-the-screen>).
* Committed cost comes from F6 purchase orders ([EVE-63](<https://linear.app/resnovas/issue/EVE-63/f6-warehousing-and-inventory-equipment-stock-availability-purchasing>)) and approved bills not yet paid (F11.5).

## Scope

1. Dimensions on every journal line: event (F1 Event), event series (F1 EventSeries), phase (F1 Phase), department (F1 Department), plus custom dimensions (F14 custom fields can add values). Dimension values are created automatically when an F1 Event, EventSeries, Phase or Department is created (consume F1 domain events).
2. `Budget` and `BudgetLine` with versions; states draft, submitted, approved, superseded ([EVE-42](<https://linear.app/resnovas/issue/EVE-42/p13-build-the-storage-layer-drizzle-on-postgres-and-sqlite-state>) state machine). Approved versions are immutable; a revision creates a new version.
3. Actions: `accounting.dimension.*`, `accounting.budget.draft` / `update` / `submit` / `approve` (always) / `variance`.
4. Variance service: budget, committed (open F6 POs and approved unpaid bills), planned (F1 EquipmentRequirement priced from the F6 catalogue, not yet ordered), actual (posted journals) and forecast (actual plus committed plus planned) per account and phase, as of a date.
5. Screens: Event finance tab inside the F1 Event screen, Budget editor (offline capable grid). Each with projections; the agent reads exactly the figures on screen.
6. Agent rule: flag an F1 Event when forecast passes a tenant-set share of budget (default 90 percent); approval not needed to flag.

## Acceptance criteria

* Two people edit different budget lines offline on two devices; both edits survive reconnect. Same-line edits resolve last-writer-wins and the losing value is shown in history.
* Approving needs a second person with `accounting:budget:approve`; the drafter cannot approve (segregation test).
* Variance numbers for a seeded F1 Event match a hand-computed fixture.
* The agent, asked "how is the stage phase doing against budget", answers with the same figures as the Event finance tab (projection test).
