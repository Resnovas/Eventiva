## Goal

Capacity can never be oversold, even with thousands of buyers at on-sale time, because every hold, sale and release for a pool goes through one serialised owner.

## Scope

1. A `CapacityPool` Effect Cluster entity keyed by pool id, owning held, sold and admitted counters; it checks every ancestor pool (parent entities) before granting. Messages are persisted and idempotent by request id (<issue id="1b79a257-9ea0-40b5-a8f7-23e1c09221be" label="EVE-39" href="https://linear.app/resnovas/issue/EVE-39/make-every-entity-action-idempotent-and-persisted-by-default" />).
2. Actions: ticketing.hold.create, release, extend; ticketing.pool.availability. Hold purposes: checkout, manual, offline-quota. Holds expire on a durable timer and emit hold_expired.
3. Register ticketing as an F9 line provider for kind "ticket" with reserve, commit and release.
4. On-sale queue: when a sales window has the queue on, requests before and at open time get a queue position and are admitted to hold.create at a configured rate; the queue state is visible to the buyer as position and estimate.
5. Change feed events (<issue id="ee08644c-eb3c-4a46-aea7-745864ad4263" label="EVE-45" href="https://linear.app/resnovas/issue/EVE-45/p16-build-the-change-flow-domain-events-and-a-durable-resource-change" />) for availability so screens and the public picker update live; availability served from a read model, not from the entity, for public reads.
6. Capacity board shows live counters.

## Acceptance criteria

* Load test: 10,000 concurrent hold requests on a 1,000-capacity pool across two runners grant exactly 1,000 units; repeat during a runner drain and a runner kill (<issue id="37a1be99-529e-478c-a187-48c120672aeb" label="EVE-18" href="https://linear.app/resnovas/issue/EVE-18/s5-verify-sharding-across-two-independent-runners-with-drain-and" /> scenarios) with no oversell and no lost hold.
* Nested pools: a sale is refused when the child has room but the parent is full.
* A replayed hold request with the same id returns the original hold.
* Expired holds return capacity within 5 seconds of expiry.
* Availability read p95 under 50 ms from the read model under the same load.
