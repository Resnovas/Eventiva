## Binding architectural constraint — 2026-11-15: acyclic, strictly typed modules

Owner requires **no circular dependencies** (A -> B -> A, including longer transitive cycles) across Nx packages, runtime module manifests, capabilities/providers, extensions, UI/data/hook packages, TypeScript type-only imports, path aliases and generated entrypoints. Module admission MUST detect and reject cycle paths before registration/activation (with actionable cycle diagnostics), not hang or partially activate. Build CI MUST analyze both static import/re-export graph (value and type-only, barrels, aliases, indirect transitive edges) and runtime manifest dependency graph; include fixture A->B->A and A->B->C->A, valid shared-contract A->C<-B, and provider capability registration that allows observation without reverse imports. Dynamic hook subscriptions are one-way via central typed registry and must not create inverse module dependencies.

**Strong typing is a hard gate:** Do not use `any`, explicit `unknown`, an untyped `none` placeholder (or equivalent erased value), unsafe casts (`as any`, `as unknown as T`), `@ts-ignore`, `@ts-nocheck`, weakened eslint checks, blind JSON casts, or untyped external module bindings to sidestep dependency problems. Enable strict TS checks (`strict`, `noImplicitAny`, `strictNullChecks`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` as compatible with codebase) and typed ESLint checks. Public Effect action contracts, schemas, Context.Tag services/Layers, typed failures, providers, hook payloads, resource declarations, and external dependency imports must preserve precise inferred input/output/error/environment types. TypeScript's lowercase `none` is not a built-in type: use explicit domain unions/Option/Result where absence is required, not a catch-all placeholder.

For *inherently untrusted external input*, never claim it is statically validated: use Effect Schema decode/validation at the boundary before data reaches the typed domain; if a low-level vendor API forces `unknown`, isolate it privately in a narrow, reviewed adapter and expose only a parsed precise type. This is a proposed unavoidable exception requiring explicit owner review, not implicit approval to use `unknown` broadly. Prefer generic typed Schema.DecodeUnknown signatures where required by Effect library, but do not allow such unknown values to leak into module APIs. If a third-party package lacks accurate declarations, use an audited and tested typed adapter/declaration rather than any/unknown; escalate unresolved type incompatibility for decision instead of suppressing it.

Contract extraction: when A and B both require a shared type, place a *domain-neutral, versioned public contract* in dependency C (or existing @eventiva/contracts/@eventiva/schema), with one-direction edges A->C and B->C; do NOT create C->A/B, duplicate types, use interface structural widening that weakens schema invariants, or hide a cycle through dynamic imports. No unnecessary proliferation of C packages—prefer existing stable low-level packages. Generated types are validated against live Effect Schema and external version pins.

Acceptance: run affected project typechecks, strict lint, Nx dependency graph/cycle checker, import graph checks including type-only imports and indirect aliases, Effect Schema runtime/decode and type-level compile fixtures (tsd / expectTypeOf where available) and unchanged feature compile with swapped providers. Fail CI on a cycle, `any`/erased type escape, unauthorized `unknown`, unchecked external typing, or schema/type divergence. Show negative tests that genuinely fail, positive shared-contract graph, full baseline check, and report any existing violations separately (do not silently weaken rules). Owner approval required before changes to main/settings/dependencies/verification gates.
