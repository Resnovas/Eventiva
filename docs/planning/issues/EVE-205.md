## Goal

On the day, managers see where crew are on the site map, and crew correct the map to where things were actually built, without the system ever pretending a stale position is current.

## Scope

1. A `live` layer source "Crew" registered by F10 that reads F7's position stream for rostered crew of the map's event (F2 roster), filtered to positions whose source is `crew` (F7 tags each position `unit` or `crew`; collection covers crew on a current F2 Shift of a live event who opted in, per event, off by default), with staleness from the F7 rule (2 minutes) and age shown in text, never only by colour.
2. Live map screen: crew and unit layers together, filters by department, tap a person to see their post (F2) and last update age.
3. `sitemap.live.reportLocation`: crew mark where a feature actually is (as-built); stored on the feature mirror with audit; the planned geometry stays until a manager accepts the move (`sitemap.feature.move` with the as-built position).
4. Viewer rules: department leads see their team, production managers see all, crew see others only if the event setting allows.

## Acceptance criteria

* A crew position reported through F7 appears on the F10 live map within 5 s and shows stale with its age after 2 minutes.
* A viewer without permission for a department sees no positions from it (negative test).
* As-built reports are listed for a manager and accepting one moves the feature with an audit entry.
* With `f10-live-positions` off, the crew layer is not registered.

## Constraints

No second location collector; no positions in telemetry or agent memory; Effect-TS v3; no new dependency without approval here; ships to main with check results.
