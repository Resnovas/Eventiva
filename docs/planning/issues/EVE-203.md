## Linear description

## Goal

A lighting head imports the fixtures they use, places them on the plan, and gets a correct DMX patch (universe and address per fixture) with overlaps caught before anything reaches a console.

## Context

* Parent: <issue id="fbcff205-decd-464a-b8ab-a1278e71fbe4" label="EVE-73" href="https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show" /> sections 4, 5 (FixtureType, PatchEntry), 6 (Patch screen), 8 (`FixtureLibrary`), decision D4.
* GDTF (General Device Type Format, DIN SPEC 15800) is an open zip plus XML format describing a fixture's modes and channels. Users import files they have; an online lookup on the public GDTF share is a later adapter and needs its own approval.
* Uses DesignElement from F1.6.

## Scope

1. Table `fixture_type` (org-wide: manufacturer, model, modes with channel count and footprint, weight_kg, power_w, source file ref) and `patch_entry` (element_id, mode, universe 1 to 63999, address 1 to 512).
2. `FixtureLibrary` port with a GDTF file adapter that reads manufacturer, model, modes, channel counts, weight and power. Shares the zip and XML dependency approved on F1.6; if F1.6 is not approved yet, request it here.
3. Actions: `fixtureType.import`, `fixtureType.list`, `patch.assign`, `patch.autoPatch` (fills the next free addresses per universe in unit number order, respecting a start address and per-universe gaps), `patch.check` (overlaps, address beyond 512, unpatched fixtures, mode changes that broke a footprint).
4. Pure patch functions (footprint, overlap, auto patch) in plain TypeScript with exhaustive unit tests.
5. CSV patch export through the `ConsoleExport` port from F1.5; export refuses while `patch.check` reports a conflict.
6. Agent: proactively flags conflicts and offers an auto patch, applied only on confirmation.
7. Screen: Patch (grid per universe showing occupied ranges, conflict list, assign and auto patch) with projection and bound controls.

## Acceptance criteria

* Importing three real GDTF files from the public share creates fixture types with correct mode channel counts (fixtures committed as test fixtures with their licence noted).
* Auto patch of 24 units in a 16 channel mode from 1/1 gives 1/1, 1/17, ... with no overlap and stops at 1/497 before wrapping to universe 2.
* Two offline patches to the same address both sync and `patch.check` reports the overlap; CSV export fails until resolved.
* Changing a fixture's mode to a larger footprint flags the new overlap.
* Screen passes the unbound-control check and axe.

## Constraints

Effect-TS v3 house rules (patch maths is pure TypeScript); every operation is an inventory action with one permission check, audit and change record; UI from Rambo-UI, WCAG 2.2 AA; behind PostHog flag `f1-production-plans`; no new dependency without Jonathan approving it on this issue; imported GDTF files keep their source attribution; whitelabel ASCII copy; people docs and ai-docs in the same commit; ships to main with `node --run check` results here.

## Done signal
