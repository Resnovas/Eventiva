## Linear description

## Goal

A production manager builds the timed running order of a phase, with each department's notes in its own column, and publishes it to the team, clients and (for public segments) attendees.

## Context

* Parent: <issue id="fbcff205-decd-464a-b8ab-a1278e71fbe4" label="EVE-73" href="https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show" /> sections 4, 5 (RunOfShow, Segment), 6 (Run of show editor), decision D3 (fixed and relative timing with live drift).
* Market reference: collaborative rundowns with segment durations, over and under run, department columns and read-only shares (<issue id="fbcff205-decd-464a-b8ab-a1278e71fbe4" label="EVE-73" href="https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show" /> section 3).
* Live calling of the run of show is F1.12; this slice is planning and publishing only.

## Scope

1. Tables `run_of_show` (event_id, phase_id, status: draft, published, locked; version) and `segment` (title, sort_key, timing kind: fixed start or after previous; start, duration, space_id, owner member, department columns as a map keyed by department_id, audience: internal or public, script as a Yjs text document).
2. Timing engine as a pure function: computes planned start and end of every segment from fixed and relative timings, flags overlaps, gaps and total overrun against the phase end. Plain TypeScript, no IO, fully unit tested.
3. Actions: `runOfShow.create`, `runOfShow.publish` (confirm; snapshots a numbered version and notifies through <issue id="9aae6a50-4a43-4327-ae6a-51d18bc69b35" label="EVE-24" href="https://linear.app/resnovas/issue/EVE-24/port-notifications-messaging-channels-and-transactional-email" />), `runOfShow.lock`, `segment.create`, `segment.update`, `segment.move`, `segment.delete`.
4. Read-only share: a published version can be shared by link to clients, and public segments feed F14's public schedule.
5. Agent: builds a run of show from a brief, re-times it to fit a new phase length, and flags overrun; changes appear as normal actions.
6. Screen: Run of show editor (sortable grid, department columns shown per viewer's departments, timing bar with overrun) with projection and bound controls.

## Acceptance criteria

* Timing engine tests cover fixed only, relative only, mixed, a fixed segment that collides with a relative chain, and timezone and daylight-saving change during a phase.
* Two offline editors insert segments in the same place; both survive in a stable order after sync.
* Publishing creates version N, notifies subscribed team members, and later edits do not change version N.
* A client link shows only the published version; a public segment appears in the public schedule feed.
* The agent turns "two hour conference, opening, three panels with a 20 minute break, close" into a valid run of show with no overrun.
* Screen passes the unbound-control check and axe.
