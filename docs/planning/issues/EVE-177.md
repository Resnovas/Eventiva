## Linear description

## Goal

Control can message one unit, a group or every unit on an event, mark a message urgent, and see who has read and acknowledged it; crews reply from MDT mode, and every message is part of the event's record.

## Context

* Parent: [EVE-71](<https://linear.app/resnovas/issue/EVE-71>) actions `ops.message.send`, `broadcast`, `acknowledge`; decision D2 (recommended: in-app text only in v1; push to talk and radio bridges are later issues).
* Channels, delivery and push come from [EVE-24](<https://linear.app/resnovas/issue/EVE-24>); this issue adds the ops channel types and acknowledgement rules on top.

## Scope

1. Channel per live event: control to unit, control to group (by capability or custom group), all units; unit to control.
2. Message: text, priority (normal, urgent), optional link to an Incident; urgent messages require acknowledgement and re-alert every 60 seconds (event setting) until acknowledged.
3. Read and acknowledged receipts per recipient; control sees a per-message receipt list.
4. Offline: outgoing messages queue on the device and send in order; incoming messages fetched on reconnect; the sender sees queued state.
5. Messages linked to an incident also write an IncidentLogEntry (F7.7).
6. Agent: may draft messages; `broadcast` by the agent always needs controller approval.
7. Later issues to file when this lands (not in scope here): in-app push to talk; radio bridge port.

## Acceptance criteria

* Urgent message to two units: re-alerts until both acknowledge; receipts show times.
* A crew member cannot message another event's channel (negative test).
* Message sent offline arrives in order after reconnect, exactly once (command id dedupe).
* Agent broadcast without approval is refused.
