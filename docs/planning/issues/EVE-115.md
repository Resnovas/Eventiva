## Goal

An organiser collects candidate suppliers for an event, compares them side by side with notes, and starts one enquiry to the chosen ones.

## Context

* <issue id="b22fbb0d-100b-47a3-8c32-eeacadc4c9fe" label="EVE-66" href="https://linear.app/resnovas/issue/EVE-66/f5-directory-and-marketplace-vendor-venue-and-professional-listings" /> sections 4 (`directory.shortlist.*`) and 6 (Shortlist screen).
* A shortlist may reference an F1 Event by id; F5 does not redefine the Event.
* Shortlists are private to the organiser tenant and work fully offline.

## Scope

1. Shortlist and ShortlistItem tables (organiser tenant scope), optional eventId, item note, added by.
2. Actions `directory.shortlist.create`, `.rename`, `.delete`, `.add`, `.remove`, all write class, no approval.
3. Shortlist screen: comparison table (kind, distance from the event location, capacity fit, price from, rating, response time), per-item notes, select items, "Enquire selected" which opens the F5.7 composer with recipients prefilled.
4. A shortlist panel on the F1 Event screen (the panel is a component F1 embeds; F5 ships it).
5. Offline: shortlists sync fully; listing summaries are cached copies refreshed on reconnect, with a stale marker when a listing was unpublished.
6. Projection: shortlist id, items with comparison values, selected ids.

## Acceptance criteria

* Tests for each action, tenant isolation, and offline add then reconnect.
* An unpublished listing in a shortlist shows as unavailable and cannot be enquired.
* The agent builds a shortlist from a search and explains each item, using only these actions.

## Constraints

Effect-TS v3; Rambo-UI; flag `directory-marketplace`; no new dependency without Jonathan approving it on this issue; ships to main with `node --run check` results pasted here.

## Done signal
