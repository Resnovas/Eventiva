## Goal

An organiser (or the agent on their behalf) can define what is for sale on an F1 Event: ticket types, nested capacity pools per admission scope (the Event, or a Phase, Space or public Segment of it), sales windows and access codes, all as inventory actions with screens bound to them.

## Context

* Parent [EVE-76](<https://linear.app/resnovas/issue/EVE-76/f8-ticketing-ticket-types-capacity-issuance-admissions-and-scanning>) sections 4, 5 and 6. F1 (<issue id="fbcff205-decd-464a-b8ab-a1278e71fbe4" label="EVE-73" href="https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show" />) owns Event, Phase, Space and Segment; F5 owns Venue; this issue references them by id.
* Price is stored as tiers (amount in minor units, currency, valid from and to); F9 computes the all-in price shown to buyers (fees, tax).

## Scope

1. Extension package `ticketing` (Nx tags per [EVE-22](<https://linear.app/resnovas/issue/EVE-22/correct-boundary-docs-to-match-lint-use-colon-tags-and-fix-the-house>)) with Drizzle schema for TicketType, CapacityPool and AccessCode on Postgres and SQLite, tenant guards ([EVE-42](<https://linear.app/resnovas/issue/EVE-42/p13-build-the-storage-layer-drizzle-on-postgres-and-sqlite-state>)).
2. Actions: ticketing.ticketType.create, update, publish, unpublish, archive; ticketing.pool.create, update; ticketing.salesWindow.set; ticketing.accessCode.create, revoke; navigation actions for the screens below. Approval policies as in [EVE-76](<https://linear.app/resnovas/issue/EVE-76/f8-ticketing-ticket-types-capacity-issuance-admissions-and-scanning>) section 4.
3. State machine for TicketType status: draft, on sale, paused, sold out, closed, archived; publish fails with a typed error when the type has no pool, no price tier or a window that has ended.
4. Validation: pool capacity cannot exceed the F1 Space or F5 Venue safe capacity when one is set; child pool sums may exceed a parent (shared capacity) but sales are always bound by every ancestor.
5. TicketType description as an embedded Yjs document ([EVE-51](<https://linear.app/resnovas/issue/EVE-51/p112-build-collaboration-yjs-for-text-and-canvas-with-record-sync-and>)); attendee questions as a schema (text, choice, checkbox, date; required flag).
6. Screens: Event tickets tab, Ticket type editor, Capacity board (read counters as zero until F8.2), each with its screen-context projection.

## Acceptance criteria

* Each action has a test for success, the permission denial and each typed error; publishing an incomplete type fails with `TicketTypeIncomplete`.
* Lowering a pool below its sold count fails with `CapacityBelowSold`.
* A member without ticketing:manage gets a denial from UI, HTTP and MCP alike (one test per surface).
* The agent, asked to "set up early bird and standard tickets, 500 capacity" for a sample event, creates drafts and asks before publishing (agent test with a scripted model).
* Parity and UI-binding checks pass.
