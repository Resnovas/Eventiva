## Goal

A vendor sees how their listing performs (views, saves, enquiries, response time, win rate) and what to improve, and the agent can explain it.

## Context

* <issue id="b22fbb0d-100b-47a3-8c32-eeacadc4c9fe" label="EVE-66" href="https://linear.app/resnovas/issue/EVE-66/f5-directory-and-marketplace-vendor-venue-and-professional-listings" /> sections 4 (`directory.insights.get`) and 10 (events and success metric).
* Product analytics go to PostHog through the <issue id="a03acb76-125b-4ead-815e-10ec986d8413" label="EVE-44" href="https://linear.app/resnovas/issue/EVE-44/p15-build-telemetry-opentelemetry-spans-on-every-call-and-a-vendor" /> tracking port, but vendor-facing numbers come from Eventiva's own records so they work offline, need no analytics consent from the vendor's visitors to be counted for enquiries, and match what the vendor can audit.
* Dashboards and widgets come from <issue id="1d65d374-8d06-4d69-a9c6-f3b66d565b47" label="EVE-30" href="https://linear.app/resnovas/issue/EVE-30/port-data-widgets-saved-dashboards-and-brand-kits" />.

## Scope

1. A per-listing daily aggregate table: views (from the public section, counted server side without personal data), shortlist adds, enquiries received, first-response time, quotes sent, quotes won.
2. `directory.insights.get` (listing:read): listingId, period; returns totals, trend series and comparisons with the previous period.
3. Insights screen with KPI tiles and trend charts from <issue id="1d65d374-8d06-4d69-a9c6-f3b66d565b47" label="EVE-30" href="https://linear.app/resnovas/issue/EVE-30/port-data-widgets-saved-dashboards-and-brand-kits" /> widgets; projection carries the metric values so the agent can answer "why are my enquiries down".
4. Improvement hints computed from rules (missing photos, no availability source, slow response time), each linked to the editor section by a navigation action.
5. Emit the PostHog events listed in <issue id="b22fbb0d-100b-47a3-8c32-eeacadc4c9fe" label="EVE-66" href="https://linear.app/resnovas/issue/EVE-66/f5-directory-and-marketplace-vendor-venue-and-professional-listings" /> section 10 from the relevant actions (this issue owns adding them across F5).

## Acceptance criteria

* Aggregates match a fixture of raw events (test).
* No visitor personal data is stored in the aggregate table (schema review in the PR comment).
* Each section-10 event appears in PostHog in a test project with pseudonymous ids and no message bodies (recorded).
