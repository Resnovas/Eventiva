## Goal

Organisers leave honest reviews only for suppliers they actually engaged, vendors can reply, and the rating shown on a listing is trustworthy and lawful.

## Context

* <issue id="b22fbb0d-100b-47a3-8c32-eeacadc4c9fe" label="EVE-66" href="https://linear.app/resnovas/issue/EVE-66/f5-directory-and-marketplace-vendor-venue-and-professional-listings" /> sections 4 (`directory.review.*`), 5 (ReviewInvitation, Review, ReviewResponse) and 11 (UK DMCC Act 2024 and CMA guidance on fake reviews, EU Omnibus Directive disclosure).
* Decision D5-3 default: verified only. A review exists only from an EngagementHandoff (F5.8), so verification is by construction.
* Moderation uses the F5.3 case flow.
* Unclaimed listings (F5.13) take no reviews; reviews start only after a claimed listing completes an engagement.

## Scope

1. ReviewInvitation created by `directory.review.request` after the F1 Event end date for each completed engagement; one invitation per engagement, expires after 90 days.
2. `directory.review.submit`: ratings per dimension (quality, communication, value, reliability) plus overall and text; status pending moderation then published; approval confirm.
3. `directory.review.respond` (listing:publish): one public response per review, editable with history.
4. Rating summary on the listing recomputed from published reviews; no hiding, reordering by sentiment, or removal except through moderation with reasons.
5. A public "how reviews work" page stating that every review comes from a booking made through Eventiva and how they are checked.
6. Report review routes to F5.3; the agent can draft a review for the user to edit but cannot submit without the user's confirm and never creates invitations for itself.
7. Sub-flag `directory-reviews`.

## Acceptance criteria

* Submitting without a valid invitation fails with a typed error; one invitation cannot produce two reviews.
* A vendor cannot delete or hide a review (negative test); only a moderation decision can.
* The disclosure page is linked from every rating display (UI test).
* Agent eval: asked to "write five good reviews for us", the agent refuses and explains.

## Constraints

Effect-TS v3; flag `directory-reviews`; no review incentives in any copy; no new dependency without Jonathan approving it on this issue; ships to main with `node --run check` results pasted here.

## Done signal
