## Linear description

## Goal

A client, vendor, artist or attendee can sign in to the same Eventiva app, see only their own record and the events they are on, keep their details current and control their consent, without the tenant giving them staff access.

## Context

* Parent <issue id="ad791a38-f528-4aec-9433-c36977bbe8e2" label="EVE-65" href="https://linear.app/resnovas/issue/EVE-65/f4-contacts-and-crm-people-organisations-relationships-and-history" /> sections 2 (external users), 6 (Portal profile), 9 (external principals) and 7 (portal invite needs confirm).
* One application for every role (<issue id="5c7aeec2-d49c-4028-9eca-1bc641d3618c" label="EVE-13" href="https://linear.app/resnovas/issue/EVE-13/establish-modular-core-foundations-for-database-adapters-expo-and" />): the portal is a permission-scoped view in the same app, not a separate app.
* External principals come from <issue id="7f612e80-3332-4acf-a74c-d35db06fe4e8" label="EVE-43" href="https://linear.app/resnovas/issue/EVE-43/p14-build-identity-and-access-orgs-authorization-user-profiles-and" />; this issue only links a principal to one Person and defines its policy.

## Scope

1. Actions `crm.portal.invite` (confirm; sends a magic link through <issue id="9aae6a50-4a43-4327-ae6a-51d18bc69b35" label="EVE-24" href="https://linear.app/resnovas/issue/EVE-24/port-notifications-messaging-channels-and-transactional-email" />) / `revoke` / `list`, `crm.self.get` / `update` (allowed fields only: names, preferred name, pronouns, language, time zone, own contact points), `crm.self.consent.update`, `crm.self.privacy.request`.
2. Policy: an external principal reads and writes only its linked Person, reads the names, dates and its own role of events it holds an EventRole on, and nothing else in F4. A vendor organisation admin (flag on Affiliation) can manage people affiliated with that organisation.
3. Changes made by an external principal show in the timeline as source `self` and can be reviewed by the owner.
4. Screens: Portal profile, Portal events list, Consent toggles. Flag `crm-portal`.

## Acceptance criteria

* Tests: an external principal cannot read another person, cannot list contacts, cannot call any `crm:read` action through HTTP or MCP; revoking access ends an open session at the next call; a vendor admin edits a colleague but not a person from another organisation.
* The agent, acting for an external principal, can update that person's phone and nothing else.
* `node --run check` green.

## Constraints

Effect-TS v3; WCAG 2.2 AA; whitelabel copy; no new dependency without approval here; ship to main with check results.
