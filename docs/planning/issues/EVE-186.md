## Linear description

## Goal

The agent watches the fleet and live operations and offers the right next step at the right time (expiring documents, services due, clashes, unacknowledged jobs, silent units), and can carry out any fleet or dispatch task a user asks for, always with approval where the parent spec requires it.

## Context

* Parent: [EVE-71](<https://linear.app/resnovas/issue/EVE-71>) section 7 (agent behaviour) and the approval column of section 4.
* The agent uses the same inventory actions as the UI ([EVE-52](<https://linear.app/resnovas/issue/EVE-52>)), reads screen projections ([EVE-50](<https://linear.app/resnovas/issue/EVE-50>)), runs durable watchers ([EVE-54](<https://linear.app/resnovas/issue/EVE-54>)) and posts into threads ([EVE-55](<https://linear.app/resnovas/issue/EVE-55>)).

## Scope

1. Watchers (durable, idempotent by subject and day): documents expiring within 30 days (F7.1); service due (F7.5); booking clashes, off-road vehicles with bookings, ineligible drivers (F7.2, F7.3, F7.4); incident unacknowledged after the event setting (F7.7); unit with no status or position update for the event setting (F7.6, F7.10).
2. Each watcher posts a suggestion with the proposed action and its input pre-filled; accepting runs the action as the user, with the approval policy applied.
3. On request: plan vehicles for an event from its F1 Phases and EquipmentRequirements, summarise the control log, answer unit status and location questions, draft hire requests and messages.
4. Approval-required list enforced by tests: dispatch assign and unassign, broadcast, hire request to a vendor, vehicle back on road, reassign on a live event; the agent never closes an incident.
5. Agent evaluation set (later linked through [EVE-29](<https://linear.app/resnovas/issue/EVE-29>)): 20 scripted scenarios with expected actions.

## Acceptance criteria

* Each watcher fires once per subject per day in a fixture run and survives a runner restart without duplicates.
* Every approval-required action called by the agent without approval is refused (one test per action).
* For journey J3, the agent's top suggested unit matches the deterministic ranking from F7.7.
* Offline: the agent answers from local data and says plainly when a live action needs connection.

## Constraints

Effect-TS v3 house rules; no zod; behind `eventiva-live-ops` (dispatch watchers) and `eventiva-fleet` (fleet watchers); no prompts or incident text in analytics by default; no new dependency without Jonathan approving it on this issue; tests with `@effect/vitest`; docs; ships to main per the AGENTS.md delivery exception with `node --run check` results pasted here.
