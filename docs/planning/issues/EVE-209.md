## Linear description

Status: Proposed (2026-11-01). Planning only. Needs vendor accounts and Jonathan's approval before work starts (decision D5).

## Goal

A holder can add a ticket to the phone's wallet, the pass shows the same signed code, and it updates or disappears when the ticket changes or is voided.

## Context

* Parent <issue id="8bd88b8d-9173-4f07-a92d-1c317836f4b2" label="EVE-76" href="https://linear.app/resnovas/issue/EVE-76/f8-ticketing-ticket-types-capacity-issuance-admissions-and-scanning" /> sections 8 and decision D5 (wallet passes after in-app, email and PDF).
* Apple Wallet needs an Apple developer pass type certificate; Google Wallet needs an issuer account. Both are vendor sign-ups this issue must not make; Jonathan approves them here first.

## Scope

1. `WalletPass` Effect service (neutral port) in core-facing contracts: create, update, revoke a pass for a ticket.
2. Two integration packages, one per wallet vendor, each wrapping the vendor API at an Effect boundary; credentials from the secrets service (<issue id="9d08c369-bac9-4eb7-b8a7-329b5ec9bff0" label="EVE-41" href="https://linear.app/resnovas/issue/EVE-41/p12-build-app-config-settings-secrets-and-credentials" />).
3. Pass content: event name, admission scope, date, holder name, signed code as the barcode; update on holder change, transfer and void (void shows as expired).
4. "Add to wallet" control on My tickets and in delivery email, bound to ticketing.ticket.deliver with channel wallet.

## Acceptance criteria

* Switching wallet vendor changes composition only (test with a fake implementation of the port).
* A pass created for a fixture ticket scans at an F8.5 scanner.
* Voiding the ticket updates the pass within 5 minutes in vendor sandbox tests.
* No vendor names in customer-facing copy beyond the platform-required button artwork.

## Constraints

Effect-TS v3 house rules; vendor SDKs or libraries only with Jonathan's approval here; behind flags `ticketing` and `ticketing-wallet`; ships to main per the AGENTS.md delivery exception with `node --run check` results pasted here.
