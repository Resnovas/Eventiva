## Linear description

## Goal

An organiser creates an event, splits it into phases and spaces, invites the team and enables departments, on any device and offline, and every other feature set can attach to these records by id.

## Context

* Parent: <issue id="fbcff205-decd-464a-b8ab-a1278e71fbe4" label="EVE-73" href="https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show" /> sections 4, 5 (canonical entities), 6 (Events list, Event overview), 9 (roles).
* This slice creates the canonical records F2 to F14 reference: Event, EventSeries, Phase, Space, TeamMember, Department. Their names and fields are fixed in <issue id="fbcff205-decd-464a-b8ab-a1278e71fbe4" label="EVE-73" href="https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show" /> section 5; changing them needs a note on <issue id="fbcff205-decd-464a-b8ab-a1278e71fbe4" label="EVE-73" href="https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show" /> and a message to the dependent sets.
* Status machine for Event: `draft -> planning -> confirmed -> live -> wrap -> closed`, plus `cancelled` from any state before `closed`. Built on <issue id="e4fa521d-c5d2-4f24-ab86-ed41def53953" label="EVE-42" href="https://linear.app/resnovas/issue/EVE-42/p13-build-the-storage-layer-drizzle-on-postgres-and-sqlite-state" /> state machines.

## Scope

1. Tables in an `f1-events` extension package (Nx tags `type:extension`, `layer:shared` for schemas, `layer:backend` for handlers): `event`, `event_series`, `phase`, `space`, `team_member`, `department`. All carry `org_id`; child tables carry `event_id`; UUIDv7 ids.
2. Actions: `event.create`, `event.update`, `event.transition`, `event.get`, `event.list`, `series.create`, `series.update`, `series.addEvent`, `phase.create`, `phase.update`, `phase.reorder`, `phase.delete`, `space.create`, `space.update`, `space.delete`, `team.invite`, `team.setRole`, `team.remove`, `department.enable`, `department.update`. Inputs, outputs, permissions and approvals as in [EVE-73](<https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show>) section 4.
3. Event roles (owner, producer, production manager, department head, show caller, crew, vendor, artist, client) registered with [EVE-43](<https://linear.app/resnovas/issue/EVE-43/p14-build-identity-and-access-orgs-authorization-user-profiles-and>) as event-scoped roles with the grants in [EVE-73](<https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show>) section 9.
4. Sync rules: per-field last writer wins; status only through `event.transition`, rejected offline transitions surface as a conflict; phases ordered by fractional `sort_key`.
5. Screens: Events list (table and calendar) and Event overview (header, status stepper, phase timeline, spaces, team, departments), each with its screen projection and every control bound to its action.
6. Domain events on the change feed ([EVE-45](<https://linear.app/resnovas/issue/EVE-45/p16-build-the-change-flow-domain-events-and-a-durable-resource-change>)): `event.created`, `event.statusChanged`, `phase.changed`, `team.changed`, for other sets to react to.
7. Cross-set contracts: register a F4 `PartyReferenceOwner` ([EVE-99](<https://linear.app/resnovas/issue/EVE-99/f44-find-and-merge-duplicate-contacts-and-import-and-export-them>)) for `Event.client_ref` and `TeamMember.contact_ref`, so a F4 party merge rewrites them; refs are F4 Party typeids. `team.invite` takes an optional `source` (for example an accepted F2 offer, [EVE-131](<https://linear.app/resnovas/issue/EVE-131/f24-build-assignments-offers-and-roster-confirmation>)); when called from an accepted offer for an external freelancer, the person's acceptance is recorded as the confirmation, so F2 can create the TeamMember without a second prompt. `Space` carries an optional `venue_room_ref` to an F5 VenueRoom; `Event.venue_ref` is an F5 Listing id of kind venue (<issue id="b22fbb0d-100b-47a3-8c32-eeacadc4c9fe" label="EVE-66" href="https://linear.app/resnovas/issue/EVE-66/f5-directory-and-marketplace-vendor-venue-and-professional-listings" />).

## Acceptance criteria

* The repository test suite passes on Postgres and SQLite (<issue id="e4fa521d-c5d2-4f24-ab86-ed41def53953" label="EVE-42" href="https://linear.app/resnovas/issue/EVE-42/p13-build-the-storage-layer-drizzle-on-postgres-and-sqlite-state" />) for every action, including tenant isolation: a user of org A cannot read or change an event of org B through UI, HTTP or MCP.
