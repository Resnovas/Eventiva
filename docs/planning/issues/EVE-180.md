## Linear description

## Goal

Organisers place real, to-scale things (tents, stages, fence panels, toilets, generators, bars, gates) from a library, and each placement can link to the record it represents so the map and the business data stay one.

## Context

* Parent <issue id="f8432c08-24bb-4690-a3e1-16ed79977eee" label="EVE-108" href="https://linear.app/resnovas/issue/EVE-108/f10-interactive-site-maps" /> sections 4 and 5 (SymbolLibrary, Symbol, MapFeature links).
* Link targets are owned by other sets and referenced by type and id only: F1 Space and DesignElement, F2 post or shift, F3 task, F6 inventory item type and asset, F7 vehicle, F8 gate and access zone, F9 sales point. A link needs read permission on the target.

## Scope

1. Tables `sitemap_symbol_library`, `sitemap_symbol`; a shipped starter library of about 60 symbols with real footprints (marquees 3x3 m to 20x40 m, stage decks, Heras-style fence panel 3.5 m, crowd barrier 1 m, toilet unit, accessible toilet, generator sizes, bar, food unit 3x3 and 6x3 m, first aid, info point, gate, tower, screen, cable ramp), each with metric defaults and an optional F6 inventory item type ref.
2. Actions: `sitemap.symbol.create`, `.update`, `.archive`; `sitemap.feature.link`, `.unlink` (from F10.2) with a link registry: other sets register a link target type with a read action and a display projection, so F10 never imports their packages.
3. Line symbols: fences and barriers placed along a polyline compute their unit count from length and panel width.
4. Linked feature card in the inspector: shows the target's projection and opens it by navigation action.
5. Broken links: when a target is deleted or the viewer loses access, the feature shows "unavailable" without leaking the target's name.

## Acceptance criteria

* A 350 m fence line with 3.5 m panels counts 100 panels.
* Linking a generator to an F6 asset shows the asset card; a user without F6 read sees the generator but not the asset details.
* Registering a link type from a test extension needs no change to F10 code (module boundary test).
* All actions pass the parity check; starter library loads offline.

## Constraints

Effect-TS v3; module boundaries per eslint (extensions talk through registered contracts, not imports); no new dependency without approval here; ships to main with check results.

## Done signal

Merged with tests green and the starter library listed in docs.
