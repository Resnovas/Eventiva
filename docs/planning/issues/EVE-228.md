## Goal

Published sites are found by search engines and AI assistants, read correctly in every enabled language, and only measure visitors who have consented.

## Scope

1. SEO settings per site and page: title, description, social image, canonical URL, `indexable`; generated `sitemap.xml` and `robots.txt` per hostname; preview links always `noindex`.
2. Structured data: [schema.org](<http://schema.org>) `Event` (name, dates, location from F1 Event and Space, offers from F8 ticket types when public), `Organization`, `BreadcrumbList`, generated from bindings, never typed by hand.
3. Agent-readable output: `llms.txt` and a clean machine view per page (headings, text, links, structured data) from the same SiteVersion.
4. Localisation: per-locale page text, `hreflang` links, locale switcher block, locale-aware dates, times and currency; untranslated text falls back to the site default with a visible editor warning.
5. Consent: a platform consent block (cannot be removed while analytics or embeds are enabled), categories (necessary, analytics, embeds), stored consent per visitor, no analytics or third-party embed loads before consent; consent text editable within required wording.
6. Analytics: page views and conversions (`form_submitted`, ticket checkout started) through the tracking port after consent, pseudonymous visitor id, no form values.

## Acceptance criteria

* The reference event site's Event page validates as [schema.org](<http://schema.org>) Event in a structured-data validator (recorded here) and appears in `sitemap.xml`.
* With consent declined, no analytics request leaves the page (browser test); after consent, page views arrive in PostHog.
* A two-locale site serves correct `hreflang` pairs and falls back for one untranslated block with the editor warning shown.
* `llms.txt` lists every indexable page with its title and summary.

## Constraints

Effect-TS v3; WCAG 2.2 AA for the consent block and locale switcher; behind `f14-sites`; no new dependency without approval here; ships to main per the AGENTS.md delivery exception with `node --run check` results pasted here.
