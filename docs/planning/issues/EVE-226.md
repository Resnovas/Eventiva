## Goal

Every site is live on a platform subdomain at once and on the organisation's own domain with TLS after a DNS check, old URLs redirect, and abusive sites can be reported and taken down quickly.

## Scope

1. `SiteHosting` port (Effect service): deploy a SiteVersion, set the live version per hostname, purge cache by site or path, report status. `DomainProvisioning` port: add hostname, return required DNS records, verify, issue and renew certificates, remove. One integration package per vendor; switching vendor is composition only.
2. Platform subdomains `{subdomain}.{platform sites domain}` assigned at `sites.create`; reserved and offensive names refused.
3. `domains.add` (returns DNS records and a verification token), `domains.verify` (polls DNS through the port; durable retry for up to 72 hours), `domains.setPrimary` (others 301 to primary), `domains.remove` (`always` approval for the agent). Apex and `www` both supported.
4. Redirects: exact and prefix rules, 301 and 302, CSV import (`confirm`), loop detection, applied at the edge before rendering; automatic redirects when a page path changes after publish.
5. Abuse: `sites.reportAbuse` (public, rate limited) into a takedown queue; platform operators can suspend a site (serves a neutral suspended page) through an operator-only action; the publish content checks from F14.10 feed the same queue.
6. Site settings screen: domains with live status, redirects table, suspension banner.

## Acceptance criteria

* With the adapter in a sandbox account approved here: a site is reachable on its subdomain immediately after first publish, and a test custom domain gets a valid certificate after DNS verification (recorded here).
* Changing a published page path creates a 301 from the old path automatically; a redirect loop is refused at create time.
* An in-memory test adapter passes the same port conformance suite as the real adapter (so switching vendor is proven by tests).
* A suspended site serves the suspended page on every hostname within one minute.

## Constraints

Effect-TS v3; vendor SDK only inside its integration package with `// effect-boundary:` comments; behind `f14-sites-custom-domains` for custom domains; no vendor sign-up or new dependency until Jonathan approves on this issue; no production DNS changes without his go-ahead; ships to main per the AGENTS.md delivery exception with `node --run check` results pasted here.
