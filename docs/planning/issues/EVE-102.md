## Linear description

## Goal

People can group contacts by tag, hand-picked list or saved filter, and other sets (ticketing, sales, a later marketing set) can use those groups as audiences.

## Context

* Parent [EVE-65](<https://linear.app/resnovas/issue/EVE-65/f4-contacts-and-crm-people-organisations-relationships-and-history>) sections 4 and 5 (Tag, List, SmartList).
* Search across resources is [EVE-26](<https://linear.app/resnovas/issue/EVE-26/port-search-and-embeddings-across-every-resource>); smart lists use structured filters on F4 fields and do not need embeddings.

## Scope

1. Tables `tag`, `party_tag`, `list`, `list_member`, `smart_list` (named SmartList, not Segment, which is an F1 run of show entity; Effect Schema filter definition over Party, Person, Organisation, EventRole, consent state and `lastInteractionAt`).
2. Actions `crm.tag.create` / `rename` / `delete` / `apply` / `remove`, `crm.list.create` / `update` / `delete` / `addMembers` / `removeMembers`, `crm.smartList.create` / `update` / `delete` / `evaluate`.
3. SmartList evaluation runs on Postgres online and on SQLite offline over the locally synced subset, with a flag in the result saying which.
4. An `Audience` contract (list or smart list id to party ids, respecting consent purpose) exported for other sets.
5. Screens: FilterBar save-as-smart-list on Contacts list, Lists page, tag chips on detail pages.

## Acceptance criteria

* Tests: tag set merge offline follows the add-wins rule; smart list results equal on Postgres and SQLite for the same data; Audience excludes parties without consent for the requested purpose.
* The agent builds "venue contacts in Manchester we have not spoken to this year" as a smart list from that sentence.
* `node --run check` green.

## Constraints

Effect-TS v3; WCAG 2.2 AA; no new dependency without approval here; ship to main with check results.
