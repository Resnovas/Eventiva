## Linear description

## Goal

An organiser can build a catalogue of products and variants with prices per price list and a tax category, attached to F1 Events, and every surface (UI, agent, MCP, HTTP) reads and writes it through the same actions.

## Context

* Parent <issue id="7d939472-20ba-4512-b231-c0f04c05574c" label="EVE-107" href="https://linear.app/resnovas/issue/EVE-107/f9-online-and-in-person-sales-storefront-point-of-sale-orders-payments" /> sections 4 and 5. First F9 slice; everything else builds on it.
* Money type shared across Eventiva: `Money { amountMinor: integer, currency: ISO 4217 }` with Effect Schema, safe add, subtract, multiply by quantity and allocate (split a total across lines without losing a minor unit). Lives in the shared schema package from <issue id="c31b6b08-1532-4a7a-945f-24a70bbab765" label="EVE-23" href="https://linear.app/resnovas/issue/EVE-23/split-core-into-portable-contracts-and-backend-runtime-with-a-shared" /> so F8, F11 and others reuse it.
* Tax codes and rates belong to F11 (<issue id="158ba369-976e-47ea-9f86-a8df608cb4d0" label="EVE-69" href="https://linear.app/resnovas/issue/EVE-69/f11-accounting-ledgers-invoices-bills-event-budgets-and-tax" />). F9 stores a TaxCategory per product and maps it to an F11 tax code id per region.
* Products may link to an F6 Product (<issue id="928dc098-5cc9-4586-88bb-50abbe03071a" label="EVE-63" href="https://linear.app/resnovas/issue/EVE-63/f6-warehousing-and-inventory-equipment-stock-availability-purchasing" />) for stock or hire; F9 never stores stock levels.

## Scope

1. `Money` schema and pure helpers with property tests (allocation never loses or gains a minor unit).
2. Drizzle tables (Postgres and SQLite) with tenant guards: Product, Variant, PriceList, Price, TaxCategory, ProductEvent link. Product status state machine: draft, active, archived (<issue id="e4fa521d-c5d2-4f24-ab86-ed41def53953" label="EVE-42" href="https://linear.app/resnovas/issue/EVE-42/p13-build-the-storage-layer-drizzle-on-postgres-and-sqlite-state" /> state machines).
3. Actions: sales.product.create, update, archive, list, get; sales.price.set; sales.priceList.create; sales.taxRate.resolve (category plus region plus date to F11 code and rate; until F11 ships, a fixture adapter behind a `TaxCodeSource` service).
4. Price resolution: given channel, variant and time, return the price and whether it is tax inclusive; tax inclusive and exclusive both supported with rounding per line (half up, documented).
5. Product description as Yjs rich text through <issue id="a1348819-43cc-4005-8e8d-a896a761af03" label="EVE-51" href="https://linear.app/resnovas/issue/EVE-51/p112-build-collaboration-yjs-for-text-and-canvas-with-record-sync-and" />; all other fields record-synced with per-field last writer wins.
6. Catalogue and Product editor screens with projections (<issue id="91297309-acc4-4bb9-ad68-33fbc2720e5a" label="EVE-50" href="https://linear.app/resnovas/issue/EVE-50/p111-build-screen-awareness-app-state-navigation-and-the-screen" />); every control bound to an action.

## Acceptance criteria

* A product with two variants, two price lists (GBP inclusive, EUR exclusive) and a reduced tax category resolves correct prices and tax for a UK and an EU channel; snapshot tests.
* Archiving a product used by an open channel needs confirmation; agent calls get the approval prompt.
* Tenant isolation test: org B cannot list org A products through any surface.
* Parity check passes for all new actions; both screens pass the unbound-control check.

## Constraints

Effect-TS v3 house rules (Schema, typed errors with Data.TaggedError, Layers, @effect/vitest); no zod; money in integer minor units only; behind the `f9-sales` flag; whitelabel ASCII customer text; no new dependency without Jonathan approving it on this issue; ships to main per the AGENTS.md delivery exception with `node --run check` results pasted here.

## Done signal

Merged to main with tests green, a comment listing the actions and tables, and the Money helpers referenced from the shared schema package README.
