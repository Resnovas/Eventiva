## Linear description

## Goal

Every proposed assignment is checked against overlaps, qualifications and working-time law before anyone is booked, with clear reasons and an audited override.

## Context

* Slice 3 of F2 (<issue id="1c8c53a0-396b-43a7-8fb9-c138dbbc70b2" label="EVE-67" href="https://linear.app/resnovas/issue/EVE-67/f2-scheduling-and-rosters-crew-availability-shifts-offers-call-sheets" /> sections 4, 5 and 11). Rule packs are data; UK Working Time Regulations first, EU next (decision 4, recommended).
* Rules are pure functions so they run on device offline and in the solver (F2.11).

## Scope

1. A pure rules engine in plain TypeScript (no IO): input an assignment set plus context (person age band, contract type, qualifications, existing bookings across person, vehicle and kit resources), output RuleResult\[\] with severity block, warn or info and a human-readable reason.
2. Built-in rules: overlap (any resource), travel buffer between locations (fixed minutes until a TravelTime port exists), qualification missing, daily rest, weekly rest, break entitlement, weekly hours average over the reference period with opt-out flag, young worker limits, maximum consecutive days.
3. Rule pack `uk-wtr-1998` with the limits listed in <issue id="1c8c53a0-396b-43a7-8fb9-c138dbbc70b2" label="EVE-67" href="https://linear.app/resnovas/issue/EVE-67/f2-scheduling-and-rosters-crew-availability-shifts-offers-call-sheets" /> section 11; pack `eu-wtd-2003` as a second pack; org overrides per contract type, versioned.
4. Actions `rules.check` (read), `rules.override` (approval always, justification required, audit record), `rules.pack.update` (admin).
5. RuleResults recomputed on the server after every sync and stored; device results are advisory.

## Acceptance criteria

* Table-driven tests for every rule, including a shift ending 23:00 followed by one starting 08:00 (block under UK pack) and a 17-year-old on a 9-hour shift (block).
* An override by a user without `roster:approve` fails; one with it records who, why and when in audit.
* The same input gives the same result on device and server (shared fixtures).
* Rule check of a 200-person event roster finishes under 500 ms on the server.

## Constraints

Rules stay pure plain TypeScript (house exemption for pure functions); services around them in Effect; no new dependency; legal limits cited in code comments with the regulation; ships to main with `node --run check` results pasted here.

## Done signal

Merged to main with both packs, tests green, and a comment listing every rule and its source.
