## Linear description

## Goal

An organiser requests vehicles for an F1 Event or Phase, a fleet manager allocates owned vehicles or hires them in, and Eventiva never lets the same vehicle be booked twice for overlapping times.

## Context

* Parent: [EVE-71](<https://linear.app/resnovas/issue/EVE-71>) actions `fleet.booking.*`, `fleet.hire.requestFromVendor`; entity VehicleBooking; screen Fleet calendar; journeys J1 and J2.
* Builds on the booking primitives of [EVE-33](<https://linear.app/resnovas/issue/EVE-33>) (availability, bookings). F1 entities per [EVE-73](<https://linear.app/resnovas/issue/EVE-73>) section 5: a booking attaches to an Event, optionally a Phase (load in, load out) and a Space (dock or yard), and may fulfil an EquipmentRequirement (event, phase, department, catalogue ref, quantity, needed from/to). Moving people is F1 ItineraryItem kind travel, not a vehicle booking.
* Bookings are written online only; the server is authoritative and a clash is a typed error, never a merge.

## Scope

1. VehicleBooking on top of <issue id="97915f03-fb56-4efc-bb5a-15e8b62b96b2" label="EVE-33" href="https://linear.app/resnovas/issue/EVE-33/port-scheduling-primitives-for-availability-bookings-and-rosters" /> bookings, with states requested, vendor pending, allocated, released (state machine from [EVE-42](<https://linear.app/resnovas/issue/EVE-42>)).
2. Actions: `fleet.booking.request` (by vehicle or by type), `allocate`, `release`, `reassign`, `listConflicts`; `fleet.hire.requestFromVendor` creates a vendor-pending booking and a task for the hire company (F4 Organisation). Typed errors: BookingClash, VehicleOffRoad, DriverNotEligible (from F7.2), VendorNotLinked.
3. Allocation checks: overlap, road status (F7.4), driver eligibility (F7.2), vehicle capacity against the request.
4. Fleet calendar screen: rows per vehicle, bars per booking, clash highlighting; projection includes visible range, rows and clashes.
5. Hire company external view: sees only bookings of its own vehicles and can confirm or decline.
6. Approvals: agent `fleet.hire.requestFromVendor` always needs approval; `reassign` on an event that is live asks confirm.

## Acceptance criteria

* Two concurrent `allocate` calls for overlapping times on one vehicle: exactly one succeeds, the other gets BookingClash (concurrency test).
* Allocating an off-road vehicle fails with VehicleOffRoad.
* A hire company user sees only its vehicles' bookings (negative test).
* The agent can plan vehicles for an event from its Phases and transport EquipmentRequirements and present proposed allocations without writing until approved.
* Changes appear on other open calendars through the change feed within 2 seconds in the local test stack.
