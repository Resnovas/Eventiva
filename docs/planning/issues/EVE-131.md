## Goal

Schedulers put people on shifts, send them offers, and see accepts and declines arrive, ending with a confirmed roster everyone can rely on.

## Context

* Slice 4 of F2 (<issue id="1c8c53a0-396b-43a7-8fb9-c138dbbc70b2" label="EVE-67" href="https://linear.app/resnovas/issue/EVE-67/f2-scheduling-and-rosters-crew-availability-shifts-offers-call-sheets" /> sections 4 and 5). Assignment is an <issue id="97915f03-fb56-4efc-bb5a-15e8b62b96b2" label="EVE-33" href="https://linear.app/resnovas/issue/EVE-33/port-scheduling-primitives-for-availability-bookings-and-rosters" /> Booking with an F2 state machine (<issue id="e4fa521d-c5d2-4f24-ab86-ed41def53953" label="EVE-42" href="https://linear.app/resnovas/issue/EVE-42/p13-build-the-storage-layer-drizzle-on-postgres-and-sqlite-state" />).
* Offers go out through the notifications port (<issue id="9aae6a50-4a43-4327-ae6a-51d18bc69b35" label="EVE-24" href="https://linear.app/resnovas/issue/EVE-24/port-notifications-messaging-channels-and-transactional-email" />).

## Scope

1. Assignment state machine: proposed, offered, accepted, declined, confirmed, cancelled, completed; illegal transitions are typed errors.
2. Actions `roster.assign` (runs `rules.check`, blocks unless overridden), `roster.unassign` (approval always once confirmed), `offer.send` (agent confirm; batch; expiry), `offer.respond`, `offer.withdraw`, `roster.confirm` (approval always).
3. Offline: transitions replay in order at sync; accept after withdraw is rejected and shown to both sides; an offline double booking is kept, flagged on both assignments and blocks `offer.send` for them until resolved.
4. Reminders: unanswered offers produce a reminder draft after a configurable time (default 24 hours); sending it is `offer.send`.
5. Engagement type (employee, freelancer, agency) recorded on each assignment for F12. On accept, link the Assignment to the person's F1 TeamMember on the Event (<issue id="fbcff205-decd-464a-b8ab-a1278e71fbe4" label="EVE-73" href="https://linear.app/resnovas/issue/EVE-73/f1-events-and-production-planning-the-event-record-run-of-show" />), creating it through F1's action with the external flag for freelancers.
6. My schedule screen for crew (offers inbox, upcoming shifts) with projection.

## Acceptance criteria

* Assign, offer, accept, confirm round trip through UI and through MCP gives identical records and audit entries.
* Two offline devices double-book one person; after reconnect both assignments show a conflict and `offer.send` on them fails with `UnresolvedConflict`.
* An agent calling `roster.confirm` produces an approval request instead of confirming.
* Expired offers move to declined with reason `expired`.
