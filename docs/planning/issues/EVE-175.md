## Linear description

## Goal

An attendee browses an event's store on the web or in the app, checks out as a guest or signed in, pays, and gets a confirmation, with the store usable for browsing offline from cache.

## Context

* Parent <issue id="7d939472-20ba-4512-b231-c0f04c05574c" label="EVE-107" href="https://linear.app/resnovas/issue/EVE-107/f9-online-and-in-person-sales-storefront-point-of-sale-orders-payments" /> sections 6 and 11. Storefront blocks are embedded in F14 sites; F9 owns the catalogue view, cart and checkout, F14 owns page layout.
* Public reads use sales:catalogue:read on an open online channel without sign-in.

## Scope

1. Storefront screens: product list and detail for one channel, cart drawer, checkout (contact details, fulfilment choice from F9.7, consent, refund policy text, pay with the hosted payment field from F9.3).
2. Guest checkout creating or matching an F4 contact by email; signed-in checkout using the user's contact.
3. Consumer law text per product (14-day cancellation for goods; exemption for dated leisure services and tickets), marketing consent unticked and separate.
4. Confirmation screen and email through <issue id="9aae6a50-4a43-4327-ae6a-51d18bc69b35" label="EVE-24" href="https://linear.app/resnovas/issue/EVE-24/port-notifications-messaging-channels-and-transactional-email" />; order status page for the customer (own orders only).
5. Catalogue and images cached for offline browsing; checkout clearly marked as needing connection.
6. Exposed as F14 blocks (product grid, product detail, cart, checkout) with a neutral block contract.
7. Telemetry: sales_checkout_started, sales_order_placed, sales_payment_failed.

## Acceptance criteria

* Playwright run on web: guest buys two products with the fake gateway, gets confirmation, sees the order on the status page; an axe check passes WCAG 2.2 AA on every storefront screen.
* Same flow on Android development build.
* Offline: product list renders from cache; checkout button shows the offline message and does not attempt payment.
* A customer cannot read another customer's order by id through UI, HTTP or MCP.

## Constraints

Effect-TS v3 house rules; Rambo-UI components only; whitelabel ASCII customer text; behind the `f9-sales` flag; no new dependency without Jonathan approving it on this issue; ships to main per the AGENTS.md delivery exception with `node --run check` results pasted here.
