## Linear description

## Goal

Eventiva has one neutral contract for vehicle telematics (position, odometer, fault codes), so a provider can be added later by composition only, without touching fleet or dispatch code.

## Context

* Parent: [EVE-71](<https://linear.app/resnovas/issue/EVE-71>) section 8; decision D3 (recommended: port only in v1, no provider adapter until a customer needs one and Jonathan approves the vendor).
* House rule: vendors sit behind an integration package with a neutral Effect service; credentials through config and secrets ([EVE-41](<https://linear.app/resnovas/issue/EVE-41>)).

## Scope

1. `TelematicsPort` Effect service (Context.Tag): `linkVehicle(vehicleId, providerRef)`, `streamPositions`, `latestOdometer`, `faultCodes`, each with typed errors (ProviderUnavailable, NotLinked, RateLimited).
2. TelematicsLink entity: vehicle, provider key, external id, linked by, status.
3. A fixture adapter that replays a recorded route, used in tests and demos.
4. Wiring: positions from the port feed the same stream as F7.10 (source = telematics); odometer readings land as OdometerReading (F7.5) with source telematics.
5. Docs for people and agents: how to add an adapter package, what it must implement, conformance tests to pass.

## Acceptance criteria

* Conformance suite runs against the fixture adapter and passes.
* Swapping the fixture adapter for a second stub changes only the Layer composition (test proves no domain import of adapter code; Nx boundary lint passes).
* No credentials in logs, spans or action payloads.

## Constraints

Effect-TS v3 house rules; no zod; behind `eventiva-fleet-telematics`; no vendor SDK and no vendor sign-up in this issue; no new dependency without Jonathan approving it on this issue; tests with `@effect/vitest`; docs; ships to main per the AGENTS.md delivery exception with `node --run check` results pasted here.
