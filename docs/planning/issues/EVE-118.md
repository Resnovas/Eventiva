## Linear description

## Goal

Every serialised item and every road case has its own identity, tag code, history and printed label, so crews and the agent can find and track it.

## Context

* Parent <issue id="928dc098-5cc9-4586-88bb-50abbe03071a" label="EVE-63" href="https://linear.app/resnovas/issue/EVE-63/f6-warehousing-and-inventory-equipment-stock-availability-purchasing" /> sections 4 and 5 (Asset, containers, `inventory.label.print`). An Asset belongs to a Product with tracking `serialised` (F6.1); its location is derived from its last movement (F6.2).
* Containers (road cases, racks, dollies) are assets that hold other assets; packing a case moves its contents with it, as in the market check.
* Label printing goes through a neutral port; phase 1 renders PDF labels with no vendor. Photos and purchase documents use <issue id="8d8d301b-d679-4dac-95bb-c24889179cd0" label="EVE-25" href="https://linear.app/resnovas/issue/EVE-25/port-files-private-attachments-artifacts-and-document-import" />.

## Scope

1. Table `inventory_asset`: product, serial, tag code (unique per org; barcode Code 128 or QR payload), cost, purchase ref (F6.8 receipt line, nullable), in-service date, condition (`good`, `worn`, `damaged`), quarantine flag (F6.6), retired reason. Location is derived, never stored.
2. Containers: `inventory_container_content` (container asset, content asset or bulk product with qty). `inventory.container.pack` and `unpack` write movements so contents follow the container; moving a container writes one movement per content line in the same transaction; nesting allowed, cycles rejected (`ContainerCycle`).
3. Actions `inventory.asset.register` (single and batch), `get` (by id or tag code), `history` (movement timeline, inspections when F6.7 lands), `retire` (confirm; writes a movement to the virtual lost or scrap location).
4. Label port `LabelRenderer` (Effect service) with a PDF adapter; `inventory.label.print` renders asset and bin labels from a template (name, tag code as barcode and QR, org name). Network printer adapters are a later issue.
5. Screen Asset detail (Rambo-UI Card, Timeline, Badge) with <issue id="91297309-acc4-4bb9-ad68-33fbc2720e5a" label="EVE-50" href="https://linear.app/resnovas/issue/EVE-50/p111-build-screen-awareness-app-state-navigation-and-the-screen" /> projection and bound controls.

## Acceptance criteria

* Registering an asset with a tag code already used in the org fails with `DuplicateTagCode`.
* Packing 6 fixtures into a case and moving the case to a vehicle location shows all 6 at the vehicle; unpacking one at an event-site location leaves 5 in the case.
* A retired asset no longer counts in levels or availability and its history is still readable.
* `inventory.label.print` for 20 assets returns one PDF whose barcodes decode to the tag codes (test decodes them).
* Asking the agent "where is case 0412" answers from `asset.get` with its location and contents.

## Constraints

Effect-TS v3 house rules; no zod; Rambo-UI with WCAG 2.2 AA; flag `f6-inventory`; a barcode or PDF generation library is a new dependency and needs Jonathan's approval on this issue before use; people and agent docs updated; ships to main per the AGENTS.md delivery exception with `node --run check` results pasted here.
