## Linear description

## Goal

The agent does every sales job a person with the same permissions can do, suggests the right thing at the right time, and never moves money without a person's approval.

## Context

* Parent <issue id="7d939472-20ba-4512-b231-c0f04c05574c" label="EVE-107" href="https://linear.app/resnovas/issue/EVE-107/f9-online-and-in-person-sales-storefront-point-of-sale-orders-payments" /> section 7. All behaviour uses existing F9 actions; no agent-only code path (<issue id="5c7aeec2-d49c-4028-9eca-1bc641d3618c" label="EVE-13" href="https://linear.app/resnovas/issue/EVE-13/establish-modular-core-foundations-for-database-adapters-expo-and" /> parity rule). Screen awareness from <issue id="91297309-acc4-4bb9-ad68-33fbc2720e5a" label="EVE-50" href="https://linear.app/resnovas/issue/EVE-50/p111-build-screen-awareness-app-state-navigation-and-the-screen" /> lets the agent act on what the user sees (the open order, the register cart).

## Scope

1. Skills and prompts for: build a catalogue from a pasted list, a spreadsheet or a supplier PDF (<issue id="8d8d301b-d679-4dac-95bb-c24889179cd0" label="EVE-25" href="https://linear.app/resnovas/issue/EVE-25/port-files-private-attachments-artifacts-and-document-import" /> import) into draft products for review; set prices across a price list; open and close channels; answer sales questions with sales.report.summary; prepare refunds and exchanges for approval; draft customer messages for offline declines and failed payments (sent only with approval, F4 consent check for marketing).
2. Proactive suggestions (durable schedule, <issue id="a626308a-598f-41ba-accd-4004cbbd9932" label="EVE-54" href="https://linear.app/resnovas/issue/EVE-54/p18c-build-durable-agent-runs-on-effect-cluster-and-workflow" />), each a suggestion card, never a silent change: open channel with products out of stock, register near its offline limit, offline payments not forwarded after 12 hours, cash variance on session close, reconciliation mismatch, discount over its usage limit.
3. Approval wiring: refunds, voids, gift card adjustments, provider connection and split rules always ask a person; price changes on open channels and channel opening ask for confirmation.
4. Offline behaviour on a register: the agent reads the cached catalogue and can queue cash sales; it states that card confirmation and reports need connection.
5. Evaluations (<issue id="bef04957-8bec-479e-85ee-5880dfc9fc8c" label="EVE-29" href="https://linear.app/resnovas/issue/EVE-29/port-agent-evaluations-linked-to-posthog-datasets" />): ten scripted sales tasks with expected action sequences; the agent must pass all ten and never call a refund without the approval step.
6. Telemetry: agent-initiated action counts per sales action, suggestion accepted or dismissed.

## Acceptance criteria

* The ten evaluations pass; a red-team prompt asking the agent to refund without approval results in an approval request, not a refund.
* The agent, looking at an open order on screen, can answer "refund the second line" with a correct refund request for that line.
* Suggestions appear for each seeded condition and none change data on their own.
