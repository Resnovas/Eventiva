# Feature reachability and proof

This Markdown table is the canonical executable registry for implemented interface families. Paths ending in `/` match descendants; other paths match exactly. The runner obtains changed paths and the complete active TypeScript inventory independently from Git, rejects unmapped source, then follows resolved imports back to consumers using the existing workspace graph audit. Only affected entries record proof. A registry edit alone does not mark every feature affected. Full `verify` still runs every existing acceptance gate; selected proof does not replace coverage or integration tests. This inventory proves source-file coverage, not exhaustive discovery of every runtime action or future UI route; the guide and observable proof must still match the implemented interface.

Owner: [EVE-299](https://linear.app/resnovas/issue/EVE-299), [GitHub #1092](https://github.com/Resnovas/Eventiva/issues/1092), related house [RES-66](https://linear.app/resnovas/issue/RES-66) (formerly SMC-174). Shared tooling belongs to [RES-67](https://linear.app/resnovas/issue/RES-67), formerly SMC-175. Product acceptance remains with each feature's linked canonical guide. These entries describe local synthetic paths, not public deployment or release authorization. The shared-house registry proposal is not yet adopted.

Run `node --run verify:static`, then `node --run verify:features` for local changes against HEAD. For a committed change run `node tools/verification/run.mjs --base <trusted-base-commit>`. `--staged` selects the index paths, but the pre-commit guard additionally requires identical staged/working trees. `--check` validates registry structure without execution. Missing application mappings, failed commands, missing/empty test reports or skipped selected tests cannot produce a passed feature. Logs and reports go to ignored `test-output/verification/<run-id>/`; each manifest binds HEAD, base, dirty-tree digest, registry digest, selected paths, interface, command, timestamps and test outcomes.

Evidence collection requires serial scheduling: the runner executes one feature at a time and sets `NX_PARALLEL=1` for prerequisites, rejecting conflicting Nx command overrides. This evidence-specific contract does not require serial scheduling in the preceding static, test/build/parity or smoke stages; their concurrency needs separate integrated verification. Randomized fixture databases isolate rows, not the bounded PostgreSQL service and CPU used by lease-sensitive processes. The manifest records both concurrency limits. A real Nx fixture proves exclusive-resource lifetimes do not overlap; its concurrent control fails. This contract does not claim a proven cause for the historical backend replay failure, which remains preserved in the review. Do not launch concurrent evidence collections against the same fixture service.

Only the affected web shell gets browser screenshots. There is no menu in the current shell and no menu recording is generated. Internal library tests produce logs and test reports, not pretend UI captures. Tests requiring PostgreSQL use a disposable loopback `eventiva_fixture` account with synthetic data. No configured remote provider is contacted by the evidence runner. Its environment allowlist excludes API/provider keys. Native Android/iOS interaction, public MCP/ACP transport and production deployment remain unverified or unimplemented as stated below; an export is not native-device proof.

## PR fixture trust review

Reviewed the existing workflow and fixture boundary before adding the PR branch. Jonathan's approval relayed on 2026-11-19 permits synthetic candidate execution, not shared databases, deployment, secrets or production migrations. The pre-existing push/main and merge-group fixture path remains separately conditioned and runs the same database acceptance targets. Pull requests get their own disposable fixture on the job's fresh hosted runner. Manual dispatch still lacks trusted predecessor history and fails the documentation/evidence baseline requirement; it does not silently certify HEAD against itself.

The job grants only `contents: read`; checkout disables persistent credentials. It uses `pull_request`, not `pull_request_target`; no repository secrets, environment deployment credentials, host filesystem mounts or privileged container are supplied. The pinned PostgreSQL image has two CPUs, 1 GiB memory, 256 PIDs, no-new-privileges and a bounded tmpfs data directory. Its port binds loopback. A generated password grants only the synthetic `eventiva_fixture` login, CREATEDB for test isolation, and no superuser, role creation, replication or RLS bypass. Bootstrap credentials are not passed to test commands. Cleanup runs even on failure. Existing trusted-event process, cluster, migration and resource tests are retained.

The candidate still controls code on its runner, can access Docker and network, and can produce deceptive test output. This is not an adversarial sandbox or cryptographically independent attestation. Its reachable data and credentials must remain synthetic/ephemeral. PR cache writes are scoped to the PR ref and cannot publish into the trusted main ref. No broader runner-group isolation, egress restriction or secret access is claimed.

Evidence uploads use the existing Actions artifact audience and exactly seven-day retention, as approved. The runner selects affected entries from changed source and reverse imports rather than recording unrelated UI. Per-feature command logs, actual test outcomes and emitted files are bound to source, committed tree, dirty content, source inventory and registry digests. An aggregate suite remains labeled as that interface family, not proof of unimplemented transports or native devices. There are no interaction recordings in the current passive shell; any future recording must be at most 60 seconds and use synthetic inputs. This local runner does not yet validate media duration or adopt the shared manifest schema merged in house PR #56; those remain explicit adoption work, not passed checks. The [review checkpoint](../funnel-review.md#owner-decisions-and-remaining-adoption-boundaries) records the reproduced shared adoption blockers.
